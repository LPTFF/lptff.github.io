# Claude Code Project Notes

## Project facts

- This is a Vue 3 + Vite website using JavaScript and TypeScript.
- The package manager is npm; keep `package-lock.json` in sync with dependency changes.
- The application entry is `index.html` → `src/main.js` → `src/App.vue` → `src/router/index.js`.
- Page components live under `src/views/`.
- User-facing Markdown content lives under `src/content/blog/` and `src/content/interview/`.
- Runtime/static assets live under `public/`; large imported data snapshots live under `src/public/data/`.

## Commands

- `npm run serve`: sync interview summaries, then start the Vite dev server on port 8080.
- `npm run build`: sync interview summaries, run `vue-tsc --noEmit`, build with Vite, then create `dist/404.html`.
- `npm run preview`: preview the built output.
- Do not run `build.sh` or `uploadQL.js` unless the user explicitly requests crawler or deployment work.

## Generated and derived files

- `public/findJob-summary/full.md` and `public/findJob-summary/chain.md` are generated by `scripts/sync-findJob-summary.js` from `src/content/interview/full.md` and `src/content/interview/chain.md`.
- `dist/` is build output.
- `auto-imports.d.ts` and `components.d.ts` are generated declarations; avoid editing them directly unless the task targets generated output.
- `src/public/data/` contains large crawler/data snapshots. Read specific files only when the task concerns their data source or consumer.
- `public/image/` contains published image URLs used by blog content; do not move or rename it without checking compatibility paths.

## Working rules

- Keep changes minimal and scoped to the user's request.
- Before changing routes, content loading, generated paths, dependencies, or build configuration, read `.claude/project-context.md` and update it when the project structure or validation baseline changes.
- Prefer source files under `src/`, `scripts/`, `vite.config.ts`, `package.json`, and `tsconfig*.json` over generated output.
- For broad searches, exclude `node_modules/`, `dist/`, `.git/`, `.claude/worktrees/`, `src/public/data/`, `public/image/`, `package-lock.json`, `auto-imports.d.ts`, and `components.d.ts`; include them explicitly only when relevant.
- Use `vscode-context-mcp` only when VS Code/LSP context, symbols, references, or the active editor are useful; ordinary repository searches can use the standard file tools.
- Do not modify user-level Claude configuration, memory, `.claude.json`, or global settings from this repository.
- Do not add automatic hooks or scheduled tasks unless the user explicitly requests them.

## Verification

- For code changes, prefer `npm run build`.
- For type-only checks, use `npx vue-tsc --noEmit`.
- For browser changes, run `npm run serve` and inspect the Vite app.
- Report failed tests or skipped verification plainly.

## Ongoing context maintenance

`.claude/project-context.md` is the maintained project context record. Each iteration that changes architecture, directories, routes, build behavior, dependencies, generated files, or data flow must update its baseline and maintenance checklist. Small isolated UI edits only need the checklist reviewed.
