# 历史仓库收敛核对

核对日期：2026-09-27。本文记录公开待办 P01、P02、P04、P05 的源码与仓库事实，不表示历史仓库已归档、服务器已调整，或旧站已下线。运行中的扩展、外部链接访问量和第三方资产授权均需各自的直接证据。

## P01 旧版浏览器扩展

旧基金扩展的主要行为是从天天基金请求中取得 Cookie、在弹窗展示并复制，以及自动把它同步到旧服务端环境。现用 `extension/` 已有天天基金账户、持仓、详情和交易来源采集，经本地暂存交给网站投资账本；其凭据同步是独立配置和授权的局域网 HTTPS 能力，服务的来源与目的也不同。

结论：**基金数据采集已经由现用扩展承担；旧版自动同步凭据的方式没有等价替代，也不迁入现用扩展。** 旧扩展源码只作历史参照。旧扩展是否仍安装在任何浏览器中、其旧服务端授权是否仍有效，单靠仓库源码无法确认；退出运行与撤销不再需要的授权应在核对现场后单独处理。不得把旧扩展的静态配置、凭据或宽泛权限复制到公开仓库。

## P02 旧版网站

旧 `github-pages` 仓库的正式构建路径是 `/github-pages/`。其当前源码包含 Vue/Vite 模板、`About` 占位页和 `Job`、`Life` 两个只显示名称并互相跳转的页面，没有独立文章、业务数据或可迁移的产品功能。当前主体站点已有真实的职业入口、博客与生活导航，未发现对旧 `/github-pages/` 路径的源码引用。

2026-09-27 在真实 Chrome 中检查：`/github-pages/` 仍显示旧模板，直接访问 `/github-pages/Job` 和 `/github-pages/Life` 返回 GitHub Pages 404。**无需复制占位内容。** 旧站是否下线或把根路径改为主体站点跳转，是单独的发布取舍；外部是否仍有人使用旧链接尚无访问数据，不能把源码中没有引用当作无人访问。
