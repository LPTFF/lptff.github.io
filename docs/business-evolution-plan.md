## 状态核验规则

- 运行行为和可复现验证结果优先于文档描述；
- 当前源码优先于旧计划；
- 迭代日志和提交记录用于补充实施证据；
- 无法通过源码或验证确认的事项，标记为“待核验”，不得直接标记为“已完成”；
- 每次迭代只需要更新：执行摘要、当前任务、任务看板、完成证据和状态变更记录。

### 任务状态

| 状态 | 含义 |
| --- | --- |
| 待核验 | 可能已有实现，但完成情况尚未核实 |
| 待开始 | 范围和完成标准已明确，尚未实施 |
| 进行中 | 已开始实施，但未满足全部完成标准 |
| 阻塞 | 存在明确的外部依赖或未解决决策 |
| 已完成 | 完成标准全部满足，并有证据 |
| 暂时跳过 | 当前有意不投入，保留恢复条件 |
| 已取消 | 已决定不再实施，并记录原因 |

### 产品假设状态

| 状态 | 含义 |
| --- | --- |
| 假设 | 尚未验证 |
| 验证中 | 已有实现或使用观察，但证据不足 |
| 已验证 | 指标和实际反馈支持继续投入 |
| 已否证 | 证据不支持原假设 |

任务执行状态和产品假设状态分开维护。例如，导航实验可以是“暂时跳过”，但“常用入口能否减少查找成本”仍然是“验证中”。

## 1. 当前任务

<a id="inv-data-001-投资数据可信度基础"></a>

### `INV-DATA-001`：投资数据可信度基础

| 项目 | 内容 |
| --- | --- |
| 所属阶段 | 阶段 0：证据与投资数据可信度基础 |
| 优先级 | P0 |
| 状态 | 待开始 |
| 前置依赖 | 核验现有投资数据文件、生成时间字段和页面加载逻辑 |
| 首批页面 | `FundPilotPlus.vue`、`Cryptocurrency.vue` |
| 后续任务 | `INV-DATA-002`、`INV-PLAN-001` |

#### 要解决的问题

当前投资页面已经局部显示“数据更新于”，但不同数据集的来源、生成时间读取方式、过期判定和加载失败反馈并不统一。只显示一个时间，不能让用户判断：

- 这份数据来自哪里；
- 它是什么时候生成的；
- 它是否已经过期；
- 页面当前显示的是新数据、旧快照还是空数据；
- 多个数据集只有一部分加载成功时，哪些内容仍然可用。

#### 本轮范围

1. 列出首批页面实际使用的数据集和来源；
2. 定义数据集标识、来源、生成时间和加载状态；
3. 定义最新、过期、时间未知、请求失败和结构异常状态；
4. 在基金分析 Plus 和加密货币页面持续展示这些状态；
5. 保留已有数据的情况下，刷新失败不清空旧数据；
6. 对多数据集页面分别显示状态，不用一份较新的时间掩盖另一份旧数据；
7. 验证正常、过期、时间缺失、请求失败四类场景。

#### 明确不在本轮范围

- 交易前计划与理由记录；
- 保存交易决策快照；
- 交易执行结果和交易后复盘；
- 接入基金或加密货币交易账户；
- 自动买入、卖出、转账或跟单；
- 账号、云端同步和远程埋点；
- 修改后端数据生产协议；
- 扩展首页导航能力。

#### 完成标准（Definition of Done）

- [ ] 已列出首批页面涉及的每个数据集及实际来源；
- [ ] 已定义数据集标识、来源、生成时间和加载状态；
- [ ] 已定义时间缺失、时间无效、最新和过期规则；
- [ ] 页面能直接显示数据来源、生成时间和当前可信状态；
- [ ] 请求失败、解析失败或必要结构缺失时有持续可见反馈，而不是只记录控制台日志；
- [ ] 已有旧数据时刷新失败不会清空旧数据，并明确标记旧快照；
- [ ] 多数据集页面拥有独立状态和清晰的页面汇总规则；
- [ ] 已验证正常、过期、时间缺失、请求失败四类场景；
- [ ] 已记录修改文件、验证结果和遗留限制；
- [ ] 未引入交易账户、远程数据存储或交易执行能力。

#### 完成证据

实施时在本节补充：

- 代码文件和关键实现；
- `npm run typecheck`、`npm run build` 结果；
- 浏览器正常及异常场景验证结果；
- 未解决问题和后续任务。

## 6. 产品方向与核心假设

### 6.1 投资判断与复盘

- **问题**：投资数据、策略结果和外部行情分散，且数据时间和失败状态不透明；
- **核心假设**：先建立数据可信度，再记录交易前判断和交易后结果，能够减少无法解释的决策并支持复盘；
- **假设状态**：验证中；
- **当前任务**：`INV-DATA-001`；
- **演进顺序**：

```text
数据可见
  → 数据可信度可判断
  → 交易前判断可追踪
  → 执行结果可记录
  → 交易后结果可复盘
  → 策略效果可验证
  → 风险控制可量化
```

- **当前优先改善**：数据来源和时间、策略与快照对应关系、计划理由、实际执行结果、持仓集中度；
- **验证指标**：数据错误/过期/无法解释次数、交易前使用情况、记录理由的比例、计划与实际结果的关联完整度、策略被采纳/拒绝/忽略的比例；
- **决策规则**：如果只看行情不看策略，减少重复策略展示并强化筛选和风险信息；如果看策略但不记录执行，优先增加轻量记录；如果策略长期无法通过历史或实际结果验证，降级为实验信息；加密货币维护成本高且使用频率低时，保留个人实验状态，不影响基金主流程。

收益率不能作为唯一有效性指标，短期收益可能来自市场运气。

### 6.2 个人高频入口

- **问题**：每天或每周反复访问的网站需要重复寻找；
- **核心假设**：根据个人使用习惯沉淀常用入口，可以减少查找和信息切换成本；
- **假设状态**：验证中，但当前任务暂时跳过；
- **已有实现**：`src/views/home/tools/index.vue` 使用 `localStorage.frequentWebsites` 记录点击次数并展示常用入口；
- **恢复后验证指标**：查找步骤是否减少、是否仍需回到完整分类、误点和过时入口比例、常用入口是否与真实任务一致；
- **决策规则**：只有观察证明常用入口有效后，才增加最近使用、置顶、任务分类或清理能力。

### 6.3 技术学习与知识沉淀

- **问题**：文章、面试题、项目经验和技术资料难以按场景复用；
- **核心假设**：建立项目—技术—文章—面试题关系，可以提升工作决策、面试表达和长期积累；
- **假设状态**：假设；
- **后续任务**：`KNOW-REL-001`；
- **验证指标**：内容搜索和复用次数、项目案例关联次数、工作引用次数、在限定时间内找到知识的成功率；
- **决策规则**：先从真实工作和面试需求中产生关系，不先建设大规模知识图谱。

## 7. 产品边界与非目标

当前项目是面向个人使用的信息与决策辅助工作台，不是完整平台或交易系统。

当前明确不做：

- 基金或加密货币自动交易、自动跟单、转账；
- 托管用户资产或保存第三方交易凭据；
- 账号、权限、订阅、收费和云端同步；
- 评论、私信、社区协作；
- 没有明确需求支撑的 `job`、`life` 业务扩展；
- 将基金登录入口作为正式认证基础设施；
- 在没有使用证据时进行大规模路由重构、服务化或平台化。

投资页面的策略、金额、评分和收益字段均为展示和个人辅助判断信息，必须保留数据时间、来源和风险边界。外部行情、iframe、第三方数据和外部链接不保证持续可用。

## 9. 验证指标与决策规则

每一轮实施至少记录：

| 项目 | 要回答的问题 |
| --- | --- |
| 问题 | 当前要解决的具体问题是什么？ |
| 假设 | 为什么相信最小实现可能有效？ |
| 最小实现 | 本轮明确做什么、不做什么？ |
| 观察指标 | 用什么判断有效或无效？ |
| 实际反馈 | 使用数据、主观感受和失败案例是什么？ |
| 决策 | 保留、优化、合并、降级还是删除？ |
| 下一假设 | 下一轮要验证什么？ |

功能投入规则：

- 高频且能改善真实决策：优先投入；
- 高频但只是信息搬运：优先自动化或简化；
- 低频但能沉淀长期资产：小成本保留并观察；
- 低频、低价值且维护成本高：降级或淘汰；
- 只有猜想、没有使用证据：不得直接扩展成大模块。

## 10. 状态更新流程

每次迭代完成后按以下顺序更新：

1. 核对当前源码和运行行为；
2. 更新“30 秒执行摘要”的当前阶段、任务、状态和下一步；
3. 更新当前任务的完成标准；
4. 更新任务看板状态和依赖；
5. 满足完成条件后，将事项移入“已完成事项与证据”；
6. 如果暂停，移入“暂时跳过、阻塞与取消事项”，写明原因和恢复条件；
7. 在 `.claude/iteration-log.md` 记录范围、证据、文件、验证和未解决问题；
8. 运行项目规定的上下文检查，确认长期事实是否需要同步。

### 状态迁移

```text
待核验 → 待开始 → 进行中 → 已完成
                    ├→ 阻塞 → 进行中
                    └→ 暂时跳过 → 待核验
待开始 → 已取消
```

暂时跳过的任务恢复时先回到“待核验”，不直接恢复旧的“进行中”，因为源码和产品优先级可能已经变化。
