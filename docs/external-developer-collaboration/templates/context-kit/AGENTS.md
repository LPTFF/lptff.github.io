# Agent 工作规则模板

> 复制到目标项目后，请根据项目实际情况补充命令和高风险边界。不要把本模板中的示例当作项目事实。

## 行动之前

1. 先读取项目上下文文件和受影响的业务说明。
2. 明确任务目标、完成条件、影响范围和明确不做的内容。
3. 将结论区分为已确认、推断和未解决。
4. 从指定路径、直接消费者、测试入口和生成链开始定向探索。
5. 清晰且低风险的任务进行最小修改；跨模块、行为、依赖、构建、部署或不可逆变更先形成计划和回滚边界。

## 实施规则

- 保持现有行为和项目风格，除非任务明确要求改变。
- 不为了顺手优化增加无关抽象、依赖、自动钩子或重构。
- 如果发现计划外影响，说明触发证据、影响范围和确认状态。
- 不把内部推理、代码外观或单次成功响应当作验证证据。
- 删除或覆盖文件前先检查目标内容；不确定时暂停并确认。

## 验证规则

每项验证都说明：

- 运行了什么；
- 证明了什么；
- 跳过了什么以及原因；
- 仍不能证明什么；
- 剩余风险由谁负责。

根据任务类型选择测试、构建、浏览器流程、数据消费者或部署检查。首页 HTTP 200 或单次静态检查不能替代受影响流程验证。

## 收尾规则

- 本轮证据写入迭代日志；
- 仍有效的项目事实、长期风险和决策更新到项目上下文；
- 业务能力与未来规划保持分离；
- 未完成的检查和责任人必须明确写出；
- 未经用户明确要求，不自动提交、推送或发布。
