# 最小授权验证

本原则只解决一种情况：完成关键主张必须观察用户的私人登录环境、本机状态或真实数据，而主力 Agent 不应默认获得这些权限。它不是固定双 Agent 流程，也不是通用复审机制。

## 默认分工

- **人**决定目标、价值取舍、私人环境授权和高风险动作。
- **主力 Agent**完成业务理解、实现、排错以及所有不需要私人权限的真实验证。
- **授权验证者**只在必要时进入获批环境，以只读、最小范围补足一个具体证据缺口；不接管开发，不替人做价值判断。

没有私人权限缺口时，不增加验证者、任务板或报告流程。

## 进入私人环境的条件

以下条件同时成立才进入：

1. 剩余问题是可观察、可判定的具体主张；
2. 非私人环境无法提供等价证据；
3. 人明确批准目标环境、允许观察的数据、允许动作和停止条件；
4. 可以只读完成，并只回传脱敏状态、字段语义、Coverage、聚合计数和未知。

当宿主只有一个 Agent 时，也不能因为“能控制 Chrome”就自动扩大为私人环境验证角色；必须先取得同样明确的范围授权。用户要求打开某个浏览器，只授权该浏览器操作，不自动授权浏览其他标签、账户、Network 全量内容或执行交易。

## 禁止事项

- 不读取或输出任务无关的账户、资产、交易、基金名称、金额、收益、Cookie、Token、银行卡、原始页面、原始数据或完整 Network Log。
- 不创建、修改或删除真实用户数据，不执行买卖、申购、赎回、调仓、转账及其他账户操作。
- 不扩大已批准的页面、字段、时间窗和动作；无法最小化暴露时立即停止。
- 不用私人数据制作 fixture、测试、仓库样例或长期报告。

## 回传与后续

只说明：授权范围、环境、`REAL_SOURCE_PASS | FAIL | BLOCKED | UNKNOWN`、观察到的能力或缺口、对实现的影响、是否暴露敏感信息。未观察的范围不并入结论。

失败后由主力 Agent依据脱敏事实修复；需要再次进入私人环境时重新授权。完整验收状态与证据规则见[真实环境验收原则](trusted-verification.md)。
