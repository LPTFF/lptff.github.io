# 01 用户、问题与场景

**来源**：原始 PRD 第 4–5、16–29、68 节与当前产品诊断。**状态**：目标场景；当前支持程度见 [09 需求追踪矩阵](09-traceability.md)。

## 用户真正要完成的任务

用户已经能在天天基金看到产品、持仓和盈亏，但基金复盘需要完成更高层的任务：判断最近的操作是否遵守事先定义的纪律、风险是否仍在预算内、触发后是否正确执行，以及规则是否已有可信证据。

系统不应把“成功读取并展示数据”当成任务完成，也不能在缺少用户目标、风险承受能力或完整历史时替用户发明“合理仓位”和“合适减仓”。

## 五个核心问题

1. **数据足以判断吗？**
   - 持仓、现金、交易、净值和规则版本分别覆盖到什么时间？
   - 是完整、部分、过期、失败还是 unknown？
2. **当前是否违反硬规则？**
   - 单基金、总风险资产、现金底线、指数/地区/主题等暴露是否越界？
3. **最近操作是否符合事前计划？**
   - 是否存在有效计划？申请、确认和最终持仓与计划差多少？
4. **是否需要处理？**
   - 是暂停新增、创建减仓计划、等待确认、补充数据、复核规则，还是无需操作？
5. **规则是否有效？**
   - 样本、Coverage、现金流调整绩效和风险证据是否足以比较规则内外与版本差异？

## 业务任务链

```text
目的：改善投资过程一致性与风险调整后长期结果
  → 任务：建立纪律、检查偏离、复核执行、验证规则
  → 判断：能否判断 / 是否越界 / 是否按计划 / 是否需处理 / 规则是否有效
  → 信息：持仓、现金、交易申请与确认、净值、快照、规则版本、计划、基准
  → 加工：归一化、Coverage、仓位与暴露计算、计划/实际比较、现金流调整、归因
  → 表示：偏离事实、unknown 原因、Action、执行状态、Policy Evidence
  → 技术：Adapter、Ledger、Core Engine、UI、真实来源验证
```

## 核心场景

### 场景 A：今日纪律体检

用户主动同步事实。系统先判断数据是否足以做结论，再检查硬规则和待执行事项：

```text
同步新增事实
→ 显示来源、快照时间与 Coverage
→ 检查单基金/总风险资产/现金/底层暴露
→ 无偏离且数据充分：当前没有已知的纪律偏离
→ 有偏离：生成可追溯到规则版本的 Action
→ 数据不足：说明 unknown 原因，不生成确定性行动
```

“系统正常”不能只代表同步成功，也不能超出已实现规则的覆盖范围。

### 场景 B：买入后的计划—实际复核

用户在操作前记录目的、依据、计划金额或比例、预期仓位、有效期和关联规则版本。交易同步后，系统将申请、确认和操作后快照与计划比较：

- 是否按计划对象、方向、金额/比例和期限执行；
- 是否出现部分确认、失败、撤销或费用差异；
- 操作后是否造成新的仓位或暴露越界；
- 用户如何判定偏差，以及计划何时完成。

没有事前计划的交易标记为“计划外/待复核”，不能事后重写计划掩盖原始事实。

### 场景 C：移动止损复核

用户为适用基金定义基准、回撤阈值和有效规则版本。系统按可验证的日净值维护高水位：

- 创新高时止损线按规则上移；
- 未创新高时止损线不得下移；
- 净值过期、缺失或复权/分红语义不清时降级为 unknown；
- 触发意味着进入复核或赎回计划，不等同于实时交易所止损单。

### 场景 D：减仓计划与部分确认

仓位或暴露越界后，系统只根据用户事先定义的目标区间计算恢复区间所需的计划量，并展示计算依据。赎回提交后继续跟踪申请、部分确认、费用和最终持仓，不把“Action 已关闭”当成“减仓已完成”。

### 场景 E：规则证据复盘

系统按 Policy 与版本比较：

- 规则内与规则外；
- 计划内与计划外；
- 旧版本与新版本；
- 收益、回撤、下行波动、执行一致性和恢复期。

小样本、现金流缺失、Coverage 不完整或基准不可靠时只能输出不足或弱证据。单次盈利不能证明违规操作正确，简单累计盈亏不能证明规则有效。

## 典型闭环

```text
定义目标与风险预算
→ 记录操作前计划
→ 主动同步新增事实
→ Ledger 保存并合并
→ Core 判断数据可用性与规则偏离
→ 用户选择处置并记录原因
→ 跟踪实际确认与操作后状态
→ OperationReview 固化计划/实际/结果
→ Evidence 按规则版本积累
→ 用户决定保留或修改规则
```

## 交互原则

- 软件承担记忆、计算、监控、比较和追踪；用户保留目标、风险承受能力、规则取舍和关键判断。
- 事实、推导、用户判定和建议分层显示。
- unknown 是合法结果；数据不足时优先说明缺口和受影响判断。
- 不提供脱离用户 Policy 的权威 BUY/SELL 建议，不自动申购、赎回、转账或交易。
