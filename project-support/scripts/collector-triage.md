# 采集告警证据汇总：最小试用版

目标：减少收到采集告警后逐项摘抄状态、耗时、旧数据条数和 AI 状态码的工作。

输入为现有 `run_collectors.py --summary` 生成的 version 2 JSON；输出为 Markdown 或 JSON。只读本地文件，不读取环境变量、调用 AI、联网、重跑任务、改数据或发送通知。返回码 0 仅代表摘要分析完成，不代表采集成功。

在项目根目录运行：

```powershell
python -X utf8 -B project-support/scripts/collector-triage.py --summary .artifacts/keyword-ai-retry/live-collector-summary.json
```

上述是本机已有的历史真实采集摘要，其他机器需要替换成实际摘要路径。没有输入时明确失败，不内置成功演示数据。

比较两份摘要（调用者保证按旧到新；工具无法从当前摘要格式核实时间顺序）：

```powershell
python -X utf8 -B project-support/scripts/collector-triage.py --summary OLD.json --summary NEW.json --format json
```

每份输出附输入 SHA256，方便核对版本。只比较紧邻输入里的同名采集器，缺失不按成功处理。HTTP 503/429 只说明观察到错误；403 不等于密钥失效；success 不等于有新数据；保留旧数据不等于优惠仍有效。超时缺阶段日志时保持原因未知。

输出不回显原始 reason、URL、请求体和自由文本；采集器名只允许已知公开标识，未知名字用序号替代。该白名单后续新增来源时需要维护。非法/空摘要返回 2。仅支持采集总摘要；尚不支持 ecosystem、welfare-filter 的独立格式或 GitHub 原始日志。

## 已验证与边界

2026-09-08 在真实本地命令行消费两份已有真实采集摘要，共 8 条结果：包括 success、skipped、HTTP 200、0→0 和计数减少；输出逐项核对一致，输入 SHA256 不变。另执行 10 项临时合成检查，覆盖超时缺阶段、503、成功前有503、403、非空变空、自由文本不回显、空/旧版/非法状态摘要及前后状态比较。这些检查只用于工具排错。

已证明范围：本地摘要到诊断文本的读取与转换。未证明线上恢复、真实503/超时识别的完整召回率、浏览器消费、人工节省时间。没有改 CI、部署或现有采集逻辑。

## 下一步试用

先由维护者在新告警中用实际摘要试用，保留人工核对。若摘要不足则记录缺字段，不能反推事实。验证有帮助后，再评估让 CI 保存三类统一摘要、附运行 ID/提交版本/时间，并在现有告警中提供证据入口；通知策略和线上接入另行审查。

前后对比记录：事件类型、严重程度、是否有阶段日志、人工操作秒数、总等待秒数、补取证次数、正确事实数/应有事实数、错误断言数、维护时间。人工操作时间与机器等待分别计时。先采用历史事件交叉顺序回放，再观察新事件；报告样本数、中位数和范围。任何密钥误判、空输入假成功或敏感内容泄露均需先修复，不因速度快而通过。
