# Boss-Helper 上游集成

本扩展的 BOSS 直聘核心交互基于开源项目 `Ocyss/boss-helper`，固定版本为 `0.5.2.2`，提交为 `ddc15026e8c9c04e4243d98379c85856eba43ab3`。许可证见 `BOSS_HELPER_UPSTREAM_LICENSE.txt`。

## 功能边界

页面中的统计、BOSS 原生筛选区、配置、日志、职位卡片横向队列、自动投递和翻页行为均来自同一份上游源码，工作台统一命名为“自动投递”。按产品要求，已从源码中删除上游 AI、对话框、“关于&赞赏”“反馈”“帮助”等入口；AI 沟通统一由本项目的独立小助手承载。旧版自写的右侧悬浮工作台、主开关、快捷搜索词、卡片高亮/虚化、独立 Popup 配置和自写投递流程也已删除。

本项目增加 `content/boss-autopilot.js` 与 `content/boss-autopilot.css`，负责 Gemini/企业微信本地配置，以及受限额和安全预览保护的基本岗位需求沟通。“AI 沟通小助手”在职位页与信息页统一使用右上角悬浮、默认收起、可拖动的交互，并按运行状态、配置、沟通规则、日志分栏；一键启动会让当前标签进入 BOSS 沟通页。沟通参考画像只用于 Gemini 判断与回复，不生成搜索词、不修改筛选条件，也不隐藏职位。职位筛选完全沿用上游工作台。Gemini Key 和企业微信 Webhook 只进入 `chrome.storage.local`，不会复制到上游同步模型配置，也不得写入仓库、日志或导出文件。已有值会在页面加载与保存后重新填充输入框并默认遮罩，用户可主动显示或隐藏，验收截图不得在显示状态下截取真实密钥。运行日志只保留时间、会话定位、动作和结果；另在当前浏览器本地保存最多 200 条或 30 天的沟通优化样本，包含经过手机号、邮箱、证件号、账号、链接参数和凭据遮盖后的近期上下文、招聘方消息、助手建议与判断理由，不写入仓库。

AI 沟通采用“先建立匹配感、再分阶段确认”的节奏：先回应招聘方已经提供的信息，并结合候选人经历说明一处具体匹配；每轮通常只推进一个影响去留的关键问题，初聊不批量盘问薪资、社保、用工和面试流程。对话摘要显式标注招聘方与求职者，避免模型混淆双方已经说过的内容。索要简历、联系方式、身份证明或立即约面等需要本人决策的场景不会自动代办。

扩展首次升级到简历优化版本时，会在保留城市等用户已有选择的前提下，将自动投递配置更新为更宽的前端岗位覆盖：高级/资深前端、React、Vue、AI 应用前端、低代码、可视化和前端全栈等方向均可进入候选；标题与描述只对兼职、实习、短期用工、明确外包驻场、纯销售、收费培训、劳务派遣和长期出差等强冲突项进行拦截。默认薪资区间为 20–50K，公司规模与 HR 职位不作为硬门槛，活跃度、好友及同公司/同 HR 去重继续启用。画像迁移按版本仅执行一次，之后用户在工作台中的手动调整不会被每次刷新覆盖。

Popup 的“插件市场需求”下方提供“自动投递”和“AI 沟通小助手”两个独立总开关，初始均开启。关闭后，后台不会再向 BOSS 页面注入对应的脚本与样式，并刷新已打开的 BOSS 标签页使停用立即生效。沟通规则默认回复前等待 20 秒、每日 300 条、单会话 30 条；页面明确展示有效范围 5–900 秒、1–1000 条和 1–100 条，保存时仍会按相同边界校验。

企业微信岗位提醒使用机器人 `text.content` 消息。仅当模型确认必问信息全部完整、有价值标准逐项满足、判定有价值且没有待确认问题时才进入通知队列；正文只包含岗位、公司、薪资、地点、工作安排、用工方式、BOSS 会话定位和审核理由，不转发聊天原文。失败通知最多指数退避重试三次，通知状态与对话回复去重分开保存，避免通知失败导致 BOSS 重复回复。

上游明确未实现或禁用的 AI 自动回复等能力不会在本扩展中另行伪造。

## 更新与验证

1. 在 `agent/references/boss-helper-upstream` 切换到明确的上游 tag，并初始化 Git 子模块。
2. 使用上游锁文件安装依赖并执行 `build:chrome`。
3. 将 `.output/chrome-mv3` 中的 `boss.js`、`background.js`、`content-scripts/content.js` 和 `content-scripts/content.css` 同步到本目录现有对应文件。
4. 重新应用本项目批准的精简项并同步四个构建产物。
5. 重新加载未打包扩展，在普通 Chrome 的真实 BOSS 页面逐项完成交互验收。
