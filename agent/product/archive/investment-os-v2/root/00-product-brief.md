# 00 产品简报

**来源**：原始 PRD 第 1–6、59、69–70 节与当前产品诊断。**状态**：当前产品判断；实现状态见 [09 需求追踪矩阵](09-traceability.md)。

## 定位

LPTFF Investment OS 是基于个人真实投资事实运行的本地投资纪律与复盘系统。Chrome Extension 负责在授权边界内获取事实，Investment Ledger 保存带 Coverage 的长期记录，Investment Web App 负责把事实与用户事先定义的风险预算、规则和计划比较，并跟踪处置、执行结果与长期证据。

它不是天天基金数据的美化层，也不是预测市场或代替用户下单的交易系统。产品价值来自帮助用户更一致地执行自己的投资纪律，并逐步改善可重复的风险调整后长期结果。

## 目标用户

个人使用者。第一阶段聚焦已登录天天基金、希望用自己的真实数据复盘基金操作的人，不面向多用户财富管理、公开荐股或自动交易服务。

## 业务目的与边界

产品目标是提高个人投资过程的一致性、可解释性和风险可控性，为改善长期风险调整后结果积累证据。系统不承诺持续盈利，也不鼓励在策略尚无可信证据时增加借贷或衍生品等金融杠杆。

当前优先放大的“杠杆”是**决策杠杆**：让软件承担记忆、计算、监控、比较和追踪，让用户把注意力留给目标、风险承受能力和关键取舍。

## 核心判断

一次有效复盘必须依次回答：

1. **能否判断**：持仓、交易、净值和规则数据是否完整、新鲜且语义可靠？
2. **是否越界**：单基金、总风险资产、现金底线或底层暴露是否违反用户定义的硬规则？
3. **是否按计划执行**：最近操作是否有事前计划，实际金额、比例、时间和结果与计划有何差异？
4. **下一步是什么**：需要暂停新增、制定减仓计划、补充数据、复核规则，还是保持不动？
5. **规则是否值得保留**：是否已有足够 Coverage、样本和现金流调整后的证据支持保留或修改某个规则版本？

## 产品任务链

```text
投资目标、期限与风险约束
  → 建立个人投资政策和操作前计划
  → 获取带时间与 Coverage 的持仓、交易、净值和现金事实
  → 比较当前/计划/实际/规则版本
  → 识别偏离、触发 Action 或保持 unknown
  → 记录用户处置和真实执行结果
  → 按 Policy 与版本积累 Evidence
  → 保留、修改或停止规则
```

## 价值闭环

```text
事实 → 事前规则/计划 → 偏离判断 → 行动 → 真实执行 → 结果 → 证据 → 规则调整
```

收益是结果字段，不是判断一项操作正确的唯一标准。有收益但违反事前纪律的操作仍应记录为规则外操作；亏损但按规则执行也不能仅凭单次结果否定规则。

## 当前实现基线与缺口

截至 2026-08-09，当前代码已经具备本地 Ledger、Data Coverage、标准化事实、部分暴露分析、Policy 版本和有限 Action；Policy Engine 主要检查暴露上限，Behavior Engine 的异常主要是异常大额主动买入，Action 处置主要更新状态，Evidence 主要汇总数据存在性和简单盈亏。

因此当前实现只能**局部支持**风险展示和异常提示，尚不能完成操作纪律复核。以下均为规划能力，不得写成已交付：

- 事前 `InvestmentPlan` 与计划—实际对照；
- 单基金、总风险资产、现金底线的完整风险预算；
- 移动止损高水位和只上移状态；
- 按目标区间计算的减仓计划与部分确认；
- 用户处置原因、计划动作、实际执行和结果的语义化持久化；
- 按 Policy/规则版本的现金流调整绩效、基准和归因证据。

## 当前第一优先级

第一垂直切片是 **P0 操作纪律复核**，不是继续增加数据卡片：

```text
可信事实
  → 仓位与暴露护栏
  → 计划/实际对照
  → 可解释偏离
  → 处置持久化
  → 执行结果复核
```

详细需求见 [05 投资纪律需求](05-investment-discipline-requirements.md)。
