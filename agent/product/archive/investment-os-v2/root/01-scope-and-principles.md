# 范围与原则

## 当前目标

Investment OS 以本地优先的可信事实、投资纪律执行和操作复盘为主线，形成：

```text
记录 → 分析 → 改进 → 验证
```

当前第一优先级是 P0 操作纪律复核，而不是继续增加行情、数据卡片或没有后续行动的仪表盘。

## 三层项目结构

- `src/` 是页面与应用源码区。
- `project-support/` 是项目运行支持区，包含 Chrome 扩展、采集器、爬虫、静态发布资源、构建和部署工具。
- `agent/` 是维护工作台，不能成为运行时依赖。

## 产品原则

1. Fact、Inference、用户 Judgment、Suggestion 分离。
2. 数据来源、时间范围、Coverage、失败和 unknown 状态可见。
3. Local-first；云端同步、远程埋点和第三方复用单独评估。
4. 先证明事实和字段语义可信，再运行仓位、止损、减仓或绩效判断。
5. 不为缺失数据伪造新鲜度、完整性、风险偏好或确定性结论。
6. 每个偏离必须能追溯到事实时间、规则版本和计算过程。
7. Action 关闭、交易申请、交易确认和目标恢复是不同状态，不得互相冒充。
8. 收益是结果，不是纪律正确性的唯一 Oracle。
9. 真实环境验证必须脱敏，并与 Mock/Core 开发隔离。
10. 产品成功以是否降低复盘判断成本、减少重复违规和形成规则证据衡量，不以页面数量或打开频率衡量。

## 个人投资政策与风险预算

系统必须以用户明确提供的个人投资政策为约束，不能根据年龄、历史收益或账户规模自动推断风险承受能力。以下内容由用户定义并可版本化：

- 投资目标与用途；
- 投资期限和流动性需求；
- 风险承受能力与最大可接受回撤；
- 总风险资产目标区间；
- 单基金上限；
- 指数、地区、主题、资产类型或币种暴露区间；
- 最低现金或可用资金底线；
- 移动止损适用对象、基准和回撤阈值；
- 减仓目标区间和允许的执行窗口。

系统负责：

- 记忆当前有效规则及历史版本；
- 基于可信事实计算当前值和偏离；
- 在操作前模拟计划后的组合；
- 在操作后比较计划、申请、确认和最终状态；
- 按规则版本积累执行与结果证据。

系统不负责：

- 发明“标准”风险偏好；
- 在没有 Policy 时断言某仓位或减仓幅度合适；
- 用短期收益倒推用户应承担更高风险；
- 把历史相关性包装成因果或收益承诺。

## 金融产品边界

- 开放式基金通常按日净值和申赎确认运行。移动止损是复核/赎回纪律，不是盘中实时止损单。
- “合适减仓”仅表示按用户事先规则恢复到目标区间，并不代表市场择时正确。
- 不提供保证收益、持续盈利或“加杠杆后可放大收益”的承诺。
- 不自动申购、赎回、买入、卖出、转账、跟单或操作第三方账户。
- 若未来涉及借贷、融资、期权等金融杠杆，必须在策略证据、风险边界和单独授权齐备后另立需求；不属于当前范围。

## A/B 安全边界

### Agent A

不得访问真实账户、真实资产、交易明细、Cookie、Token、Raw Snapshot、登录态或完整 Network Logs。只使用人工构造且不可还原个人事实的 fixture 开发 Domain/Core/Ledger/UI 与测试。

### Agent B

只在用户明确授权的真实环境和单一验证目标内工作；不得输出或保存基金名称、真实金额、收益、原始 JSON/HTML、Cookie、Token、银行卡信息、登录状态或完整 Network Logs。只返回脱敏的 PASS/FAIL/BLOCKED、字段存在性、Coverage、unknown、语义 mapping、Required change 和 Sensitive data exposed。

Agent B 不设计 Core 规则，不决定减仓是否合适，也不修改用户的风险预算。以真实已登录 Chrome 为验收目标时，隔离 profile 不能替代真实环境。

## 明确不做

- 不保存密码、Cookie、Token、登录状态或完整网络日志。
- 不把真实账户 HTML、JSON、Raw Snapshot、银行卡、个人资产或交易明细写入工作台或 fixture。
- 不以新增通用聊天壳、普通待办或无证据 AI 建议替代投资闭环。
- 不把规划、Mock 成功或字段存在误写为真实产品能力已交付。
- 不在 Coverage 不足时输出确定性的仓位、止损、减仓或策略有效性结论。
