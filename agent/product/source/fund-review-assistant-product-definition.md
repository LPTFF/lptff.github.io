# 基金复盘助手：核心产品定义

> **来源属性**：维护者于 2026-08-15 提供的新产品诉求原文，按其结构保存。它是历史上游输入，不等于已进入当前规划或运行时；是否调整当前 Investment Review 主线、如何与既有 P0 合并，以[人的产品审查正文](../investment-review.md)为准，本文不随当前规划反向改写。

核心不是“做一个更聪明的基金分析器”，而是**把个人投资管理中不值得消耗脑力的部分系统化，只把真正困难的问题升级给通用大模型。**

## 一句话定位

> 一个以“账户状态 + 投资纪律 + 异常检测”为核心的个人投资管理系统；负责机械判断，不负责替用户做投资判断。复杂问题一键携带完整上下文进入 GPT 深度分析。

## 核心用户价值

产品解决的不是“用户不知道市场发生了什么”，而是三个成本：

**1. 管理成本**
用户不应该每天自己计算收益、仓位、资产配置偏离、交易频率、回撤、现金比例。

**2. 纪律成本**
市场波动时，人容易受到涨跌、新闻、情绪影响。系统持续用预先确定的投资原则检查用户行为。

**3. 深度分析准备成本**
真正需要思考时，最贵的不是问 GPT，而是整理：

> 我现在持有什么 → 为什么持有 → 成本多少 → 过去做过什么 → 原计划是什么 → 当前发生了什么 → 到底需要判断什么。

产品自动完成这些 Context Engineering。

---

## 产品边界

系统只做三类事情：

> **记录事实 → 机械检查 → 发现值得思考的问题**

然后停止。

不要试图：

* 每日预测涨跌
* 自动生成大量市场评论
* 给出“建议买入/卖出”
* 自建一个弱于通用模型的投资 Agent
* 用 LLM 完成可以由公式和规则完成的计算
* 强行模仿 Buffett/Munger 给出投资结论

**LLM 不是产品主体，只是 escalation layer。**

---

# 产品核心模型

整个产品只需要四层。

### Layer 1 — State：账户真实状态

建立长期、可靠的投资账户状态。

包括：

* 当前持仓
* 持仓成本
* 买卖记录
* 现金流
* 当前市值
* 盈亏
* 收益率
* 基准收益
* 最大回撤
* 资产类别
* 仓位比例
* 目标配置
* 实际配置
* 历史配置变化

这是产品最基础也是最重要的数据资产。

---

### Layer 2 — Rules：投资纪律

用户建立自己的 **Investment Policy / Investment Constitution**。

原则来自两部分：

**经典投资思想**

例如 Buffett / Munger / Graham：

* 能力圈
* 安全边际
* 机会成本
* 长期持有
* 避免因市场波动改变投资逻辑
* 少做无意义交易
* 区分价格变化与价值变化

但不要直接编码成：

> Buffett 认为 → 买入。

而要编码成：

> **需要用户回答的问题 / 可验证的行为规则。**

例如：

**交易频率规则**

> 30 天交易次数 > N → 触发“是否存在过度交易？”

**资产配置规则**

> Nasdaq 目标 40%，允许范围 35–45%。
> 超过范围 → 提醒检查，而非提示卖出。

**投资逻辑一致性**

购买时必须记录：

> 为什么买？
> 什么情况下继续持有？
> 什么情况下认为原逻辑错误？

未来操作自动与原逻辑比较。

---

# Layer 3 — Monitor：异常检测

产品最重要的输出不是资讯，而是：

> **你的投资系统现在是否正常？**

默认状态应该是：

> **今日无需操作。**

只有触发异常时才出现信息。

异常主要来自：

**Portfolio Drift**

* 某资产明显偏离目标配置

**Risk Drift**

* 集中度、波动、回撤明显变化

**Behavior Drift**

* 交易频率突然升高
* 连续追涨杀跌
* 短期改变长期策略

**Thesis Drift**

* 当前行为与最初投资理由矛盾

**Performance Drift**

* 长期显著跑输对应基准

**Cost Drift**

* 费用、摩擦成本异常

所以产品的信息结构不是：

> 今天市场发生了 20 件事。

而是：

> 今天你的投资系统有 **1 件事值得注意**。

这就是核心的信息压缩。

---

# Layer 4 — Think：认知升级

当机械规则已经不能回答问题时：

> **Deep Analyze with GPT**

但不是简单跳转：

> “帮我分析纳斯达克。”

而是自动构造一个 **Investment Context Package**：

```text
【用户目标】
长期资产增长，风险偏好……

【当前投资组合】
资产 / 权重 / 成本 / 盈亏……

【目标资产配置】
……

【本次异常】
Nasdaq 当前权重 48%
目标范围 35%-45%

【历史操作】
……

【原始投资逻辑】
……

【相关投资纪律】
……

【需要判断的问题】
当前偏离是否值得主动再平衡，
还是应该由未来新增资金自然调整？

请：
1. 分析支持与反对两方面
2. 区分事实、假设和判断
3. 检查我的原投资逻辑是否发生变化
4. 提出还缺少哪些关键信息
5. 不直接替我做最终投资决定
```

然后交给 GPT 网页版继续。

**产品真正卖的是高质量 Context，而不是自己的模型能力。**

# 首页应该极度克制

用户打开 App 最理想只看到：

**资产**

> ¥ XXX,XXX
> YTD +8.3%

**配置**

> Nasdaq　47% / Target 40% ⚠
> CSI300　21% / Target 25%
> Gold　14% / Target 15%
> Cash　18% / Target 20%

**系统状态**

> **今日无需操作**

或者：

> **1 项需要复盘**
>
> Nasdaq 已超目标仓位区间 2%。

下面只有：

**查看原因**

**深度分析 → GPT**

不要 Dashboard 堆二十个指标。

# 最重要的产品原则

可以直接成为 Agent 的产品约束：

> **Rule 1：能用确定性算法解决，就不用 LLM。**

> **Rule 2：没有异常，不制造信息。**

> **Rule 3：系统负责发现问题，不替用户作最终投资判断。**

> **Rule 4：投资大师思想用于约束决策过程，而不是生成交易信号。**

> **Rule 5：复杂认知任务交给能力最强的通用模型，不重复造模型。**

> **Rule 6：产品长期资产是账户状态、投资逻辑、行为历史和决策记录，而不是 AI 输出。**

> **Rule 7：每增加一个功能，都问一句——它是在降低用户认知成本，还是在制造新的信息？**

# MVP

第一版实际上只需要做五件事：

**① 账户管理**
基金、交易、成本、现金流、收益。

**② 目标资产配置**
用户设置目标仓位及容忍区间。

**③ 投资纪律**
维护少量可执行规则。

**④ 每日/周期复盘**
系统输出：

> 正常 / 异常 / 需要复盘。

**⑤ 一键深度分析**
把账户状态 + 历史 + 投资逻辑 + 当前异常组成 Context Package，进入 GPT。

其他诸如：

新闻聚合、AI 每日总结、预测模型、股票推荐、复杂 Agent、社区、自媒体内容，

**全部先砍掉。**

---

最终产品闭环只有这一条：

> **Portfolio State**
> → **Rule Engine**
> → **异常检测**
> → **无需操作 / 需要思考**
> → **Context Package**
> → **GPT 深度研究**
> → **用户做判断**
> → **记录决策及理由**
> → **进入下一轮复盘**

这个闭环本身就是产品。

**真正的北极星指标也不是用户每天使用多久，而应该是：用户用多低的认知成本，持续维持一个纪律化、可解释、可复盘的投资系统。**
