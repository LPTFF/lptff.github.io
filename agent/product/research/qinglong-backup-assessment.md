# qinglongBackup 数据能力评估

## 基本信息

- **状态**：已分析，安全采集基准实施中
- **项目类型**：青龙任务、公共数据采集、账户自动化和部署脚本的混合备份仓库
- **源码地址**：<https://github.com/LPTFF/qinglongBackup>
- **本地参考目录**：`agent/product/research/qinglongBackup/`（嵌套独立 Git 仓库，外层项目不跟踪）
- **许可证**：未确认
- **评估日期**：2026-07-31

## 研究目标

评估其中哪些数据采集思路能安全服务当前网站，尤其是能否通过 GitHub Actions 定期生成结构化数据；同时隔离账户操作、私人凭据、远程部署和不可审计二进制等高风险能力。

## 已确认事实

- 项目同时包含 Node.js、Python、青龙 cron、浏览器自动化、SFTP/SSH、代理、通知和原生工具，并非单一的网站数据采集器。
- RSS、东方财富公开基金详情和 Binance 公共行情中存在可借鉴的数据解析思路。
- 原脚本把采集与 LLM、账户 Cookie/API Key、通知、SFTP 上传或青龙管理耦合，不能直接复制到当前网站或 GitHub Actions。
- 部分文件包含或曾包含明文凭据和私人连接信息；本评估不记录具体值，也不把原始文件提交到外层仓库。
- 当前网站已有 Python 数据采集、`python-crawl` 数据分支和 `gh-pages` 部署链路，但缺少统一 Schema、失败保留和采集/部署隔离。

## 分类

### 现在值得做

1. 建立无认证的公共数据 collector 基础：HTTPS 域名白名单、超时、有限重试、响应大小限制和明确失败码。
2. 建立统一数据契约与校验：数据集、Schema 版本、生成时间、来源、条数、URL、时间、新鲜度和疑似敏感字段检查。
3. 采用临时文件加原子替换；采集或校验失败时保留上一份有效候选产物。
4. 使用真实公开 RSS/Atom 来源观察聚合、去重、时间排序、来源失败与保留行为。
5. 在实际 GitHub Actions、Pages 数据文件和资讯消费页面完成采集到展示的真实闭环，不能以离线输入或自设测试替代。

### 验证通过后再做

1. RSS 来源条款和 Runner 稳定性确认后，通过 bot 分支创建仅含 JSON 差异的 PR，再评估接入资讯页面。
2. 重写东方财富公开基金详情采集，与 `INV-DATA-001` 的来源、生成时间、过期和错误状态统一；不得替换包含私人持仓与策略的 `fundPilotData.json`。
3. 只使用 Binance 无认证公共 K 线接口验证行情数据集，不读取账户、不生成交易操作。
4. 逐步为现有 Python collector 增加非空、Schema、原子写入和失败保留，再将采集与部署拆分。
5. 数据契约和消费者稳定后，才考虑受保护且不强推的独立数据分支。

### 暂时不能做

- 账户签到、积分、提现、私人持仓、交易 Cookie/API Key 和自动买卖。
- root SFTP、SSH、远程删除、进程终止、服务重启和青龙管理 API。
- 私人代理、验证码绕过、浏览器登录、忽略 TLS 校验、Frida、原生 `.so` 或来源不明的混淆二进制。
- 把原仓库中的明文 secret、Cookie、私人地址或生产连接配置放入外层仓库或 GitHub Actions。
- 未确认服务条款、robots、转载许可和合理频率的高频抓取。
- 定时任务直接提交或强推 `master`、`python-crawl`、`gh-pages`。
- 在首批采集中加入 LLM 评分或推荐；它需要密钥和成本，输出不可复现，也不是当前产品主线。

## 第一批安全基准

```text
workflow_dispatch
  → 无 secrets 的公共 RSS collector
  → Schema / 非空 / 新鲜度 / 大小 / 敏感字段校验
  → 候选 JSON
  → GitHub Actions artifact
```

第一批先在真实来源和 GitHub Actions 中定位采集问题；只有实际部署页面正确消费生成数据，才能形成验收结论。下一项生产候选优先转向与投资数据可信度主线一致的公开基金详情。

## 凭据处置边界

如果原仓库中的明文凭据曾经有效，应由仓库所有者完成撤销或轮换，并评估 Git 历史和远程仓库的暴露范围。仅删除当前文件内容不能使历史值失效。在轮换和审查完成前，相关脚本保持禁用，不进入 CI。

## 成功条件

- 外层项目不跟踪原始嵌套仓库内容。
- 采集器无需 Cookie、API Key、代理、SFTP 或私人网络。
- 真实白名单来源生成结构化结果；实际出现空数据、格式异常、超限和非白名单来源时明确失败。
- 失败不会覆盖上一份有效候选产物。
- Actions 只有读权限，只上传短期 artifact，不发布到生产分支。

## 停止条件

遇到以下任一情况时停止该来源：要求登录或绕过验证；许可边界无法确认；Runner 访问频繁失败或限流；响应包含私人信息或疑似凭据；字段、条数或文件大小异常；需要高频重试才能维持成功。

## 未解决问题

- 各候选数据源的服务条款、robots、转载许可和长期稳定性仍需逐个确认。
- 动态 `/data/*.json` 在 GitHub Pages 生产环境中的真实服务契约仍需单独核验。
- 原仓库中已暴露凭据是否全部轮换、历史是否需要清理，需由仓库所有者确认。
- 现有 Python 采集和强推发布链路何时拆分，需在首批安全基准验证后单独规划。
