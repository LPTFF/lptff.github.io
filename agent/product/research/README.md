## 使用原则

1. **保留来源**：记录项目名称、官方地址、许可证和查阅日期，确保结论可追溯。
2. **提炼问题，不只抄方案**：先说明对方解决了什么问题，再分析其方案成立所依赖的用户、数据和技术条件。
3. **区分事实与判断**：将实际观察、推断、适用性判断和未知项分开记录。
4. **先验证再采用**：任何借鉴项进入项目前，都要设计最小实验和验收指标；不得直接写入项目上下文作为已确认事实。
5. **避免照搬代码**：引入代码、资源、设计或数据前必须核对许可证、署名、隐私和安全边界；不提交来源不明或不兼容的内容。
6. **保持独立演进**：优先借鉴原则、边界和验证方法，而不是复制其他项目的完整架构。

## 推荐流程

1. 复制 [单项目参考模板](project-template.md)，按 `项目名.md` 命名。
2. 填写来源、观察事实、解决的问题和成立条件。
3. 提炼不超过三个高价值借鉴点，并说明不适用内容。
4. 为候选借鉴项定义最小验证实验、成功指标和停止条件。
5. 验证通过后，再将结论同步到业务规划、技术设计或具体实现任务；验证失败则保留原因，避免重复试错。

## 状态约定

- **待研究**：仅收录来源，尚未形成可靠判断。
- **已分析**：已完成适用性分析，但尚未验证。
- **验证中**：正在通过原型、数据或用户反馈验证。
- **已采纳**：验证通过，且已进入正式规划或实现；必须链接对应文档或提交。
- **不采纳**：当前不适用，记录原因和未来重新评估的触发条件。

## 安全与合规边界

- 不在本目录保存账号、令牌、内部地址、个人隐私数据或未公开资料。
- 不把第三方宣传文案当作已验证事实，优先引用官方文档、源码和可复现实验。
- 涉及第三方代码时记录许可证；许可证不清楚时只记录思想和公开链接，不复制实现。
- 涉及远程服务、数据上传、追踪或 AI 服务时，单独评估隐私、成本、可靠性和退出方案。
