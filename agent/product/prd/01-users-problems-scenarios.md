# 01 用户、问题与场景

**来源**：PRD 第 4–5、16–29、68 节。**状态**：产品场景基线；当前实现以源码为准。

## 用户问题

个人投资者通常能看到基金产品，却难以持续回答：当时为什么买、实际承担了什么底层风险、当前是否违反自己的规则、哪些行为长期有效。数据分散在真实平台、交易流水和每日盈亏中，历史覆盖还可能不完整。

## 核心场景

### 事实同步

用户在天天基金正常登录并主动触发同步。扩展只获取页面已经成功加载的支持数据，记录账户、持仓、每日盈亏、交易和覆盖范围。没有实际加载的历史不标记为完整。

### 系统检查

Investment 页面从本地 Ledger 读取事实，显示系统状态、组合风险、待处理行动和最近变化。正常时明确告诉用户当前无需操作；异常时只呈现需要重新判断的事项。

### 规则执行

用户把投资方法表达为目标仓位、定期投资、额外投资、暂停和复核规则。系统根据实际组合检查是否触发，历史规则版本不得被覆盖。

### 行为复盘

系统根据时间、金额、方向、资产类型和来源识别系统定投、主动买入、主动卖出、再平衡或未知交易。新行为只在必要时让用户确认一次。

### 长期证据

按规则和行为比较投入、收益、XIRR、TWR、最大回撤、偏离次数和证据强度。小样本只能标记不足，不能生成强结论。

## 典型旅程

```text
用户正常投资
→ 主动同步新增事实
→ Ledger 保存并合并
→ Core 重新计算
→ Policy 检查
→ 无异常：今天无需操作
→ 有异常：用户做一次判断
→ 系统持续观察结果
→ Evidence 积累并支持规则调整
```

## 交互原则

软件承担计算、记忆、监控和验证；用户保留目标、风险承受能力、规则取舍和关键投资判断。不要把自动推断、建议或未来规划呈现成真实事实。
