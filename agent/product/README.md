# 产品工作台

这里首先帮助人理解产品，而不是展示 Agent 的文件组织。当前产品价值、边界和验收应在一次主文档阅读中完成；工程细节按需下钻，不作为理解产品的前置条件。

## 持续回答的产品问题

**一个现代普通人的最小可持续生存系统由哪些模块组成，哪些能力必须掌握在自己手里，哪些可以安全地外包给社会？**

项目通过功能的新增、维护和真实使用持续回答这个问题。现有投资复盘、资讯与福利筛选、导航、知识资产和娱乐已经在承担其中不同的作用；这些作用需要在使用中继续检验，不因功能存在就认定价值已被证明，也不因概念上缺少某个模块就另建一套管理系统。

“智力外包、决策保留”是主要分工：在授权与可信边界内，让工具和社会服务承担获取、整理、计算、比较、分析及可观察结果的追踪；人保留目标、重要代价的取舍、授权、否决与更换方案的能力。“最小”关注人长期需要亲自承担的劳动、注意力、维护与依赖成本，同时保有必要的理解和恢复能力，不能用页面或功能数量衡量。

项目不能以持续获得顶尖付费模型为前提。模型不可用时，允许分析深度和开发速度下降，或减少、暂停辅助能力，但不应阻断可独立运行的核心功能，也不应把全部任务转回用户手工承担。功能复杂度以长期可承受的理解和维护成本为界；这些是设计要求，是否满足仍需对应验证。

这是一项持续的产品判断，不是新的功能需求或固定路线图。具体需要可以支持新增功能；维护也可以选择简化、合并、替换或退出。完成一次工具任务、获得休闲体验、确认当前无需处理，都可以是有效结果，不要求每次使用再填写记录或复盘表。

## 站点产品组合

| 方向 | 定位 | 当前优先级 | 启动或继续条件 |
| --- | --- | --- | --- |
| Investment Review | 第一主线：先完成个人投资纪律与执行闭环，再逐步测量、归因、评价和学习 | **P0** | 先交付操作/仓位/止损/减仓复盘；绩效链按具体证据条件在 P1–P4 启动 |
| Contract Review | 冻结的合约交易复盘验证原型：只保留真实事实、确定性统计和本人规则对照 | **冻结** | Investment Review 完成 3–5 个真实复盘周期并证明减少遗漏、重复错误或复盘时间后，才重新审查；边界见[产品正文](contract-review.md) |
| 职业资产 | 第二主线候选：沉淀可复用的项目成果与证据 | P1 候选 | Investment 至少完成一轮真实复盘闭环，且出现明确工作、面试或谈薪需求 |
| 健康精力 | 第三主线候选：观察行为与工作状态关系 | P2 候选 | 记录习惯、隐私和非医疗解释边界明确 |
| 通用决策复盘引擎 | 长期抽象 | 暂不实施 | 至少一个领域证明稳定共性，避免提前做通用表单 |
| 导航、资讯、博客、学习 | 入口和内容资产 | 维护/支撑 | 有明确访问、检索或复用问题时才扩展 |
| 通用聊天壳、复杂多 Agent | 非目标 | 不做 | 只有服务已验证闭环且可审查时才重新评估 |

职业与健康不与 Investment 主线同时建设完整模块。站点现有路由和功能事实需要深查时，看[站点能力清单](reference/site-capability-inventory.md)。

Investment Review 在完成至少 3–5 个真实复盘周期，并出现“减少遗漏、减少重复错误或缩短完整复盘时间”的使用证据前，不启动其他完整产品建设。源码可运行、构建通过或一次页面验收都不满足这个门槛。

## 产品判断规则

功能新增、维护和使用反馈，按当前问题的重要程度关注：

1. 这项功能支持人的什么需要，用户最终要完成什么任务、判断或体验；
2. 所需私人或外部数据是什么，来源与删除边界是否清楚；
3. 哪些劳动由系统或社会服务承担，哪些选择与必要能力仍由本人掌握；
4. 节省了哪些工作，又增加了哪些输入、阅读、切换、核查、维护或依赖成本；
5. 用户是否能理解结果意味着什么、不能证明什么、下一步是什么；
6. 真实使用是否支持继续保留、优化、合并、替换或退出；重复使用型功能可在三到五次使用后回看，一次性工具不强制建立长期复盘。

这些问题由维护者结合已有上下文和使用反馈回答，不新增强制报告、打分表或用户填写流程。缺字段、长期未访问或没有新记录，本身不构成要求用户处理的现实问题。

需求分析遵循[业务任务分析执行规范](../standards/business-task-analysis.md)，页面和交互遵循[产品设计标准](../standards/product-design.md)。功能名称只是候选手段；证据不足时保留 unknown，不为文档完整性虚构目的。

## 冲突时相信什么

```text
真实运行与匹配的可信验证
→ 当前源码
→ 活动产品正文中的 Current State
→ 目标产品与工程契约
→ source / archive 历史资料
```

下层事实可以否证上层规划。PRD、Mock、构建成功、HTTP 200 或页面出现都不能单独把能力升级为已实现。

## 资料边界

- [investment-review.md](investment-review.md)：当前需求、当前事实、分工、状态和人的验收的唯一 owner。
- [reference/investment-review-engineering.md](reference/investment-review-engineering.md)：领域对象、公式、不变量、真实环境验收、隐私协议和历史任务映射；不维护另一份产品状态。
- [reference/site-capability-inventory.md](reference/site-capability-inventory.md)：基于源码的站点级能力清单，不描述未来规划。
- [source/](source/)：用户输入和历史来源，只用于追溯。
- [archive/](archive/)：已被替代的 PRD 和文档体系，不参与当前任务解析。
- [research/](research/)：外部研究和比较，不自动成为产品规则。

不要新增并行 roadmap、Agent 独立任务板、第二份 current-state 或 traceability。只有新资料能减少人的搜索、识别、比较或整合成本时才创建文件。
