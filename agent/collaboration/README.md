# 外部开发者协作资料

本目录是项目与外部开发者交流 Agent 管理、项目上下文和可审查开发实践时使用的公开资料包。

它不复制任何公司内部模板，也不承载企业内部项目、客户、账号、凭据或未公开决策。目录中的内容只描述可以公开讨论、复用和反哺开源社区的方法论、沟通格式和审批边界。

## 1. 协作模型

```text
公司项目内部实现
    │ 适配：组织权限、合规要求、内部工具和项目约束
    ▼
内部 Agent 管理模板（不对外复制）
    │ 提炼：去除组织特定信息，只保留通用问题和可复用方法
    ▼
公开方法论与脚本（本目录及开源项目）
    │ 经过脱敏、技术审查和发布审批
    ▼
开源文档或脚本 PR
```

三层之间的边界是本目录的核心约定：

- **内部实现层**：公司项目可以使用适配后的 Agent 管理模板，但模板中的权限、系统、客户、业务数据、内部路径和组织流程不公开。
- **方法论层**：开源项目继续作为公开方法论来源。外部交流优先讨论目标、约束、证据、验证和可复用模式，而不是交换内部配置原文。
- **反哺层**：只有经过脱敏和审批、并且对其他项目具有通用价值的改进，才整理为独立的文档、脚本、测试或示例提交到开源项目。

### 可复制模板包

需要直接复制到其他项目时，使用 [templates/context-kit/](templates/context-kit/)：

- `AGENTS.md`：Agent 工作规则和验证门槛；
- `CLAUDE.md`：项目命令、目录、生成文件和验证基线；
- `agent/context/project-context.md`：当前事实、关键决策和未解决问题；
- `agent/context/iteration-log.md`：每轮变更和证据；
- `agent/product/business-overview.md`：当前业务能力；
- `agent/product/business-planning.md`：未来规划和验收标准。

复制后必须先补充目标项目的实际命令、路径和边界，再让 Agent 使用；模板中的占位符不是项目事实。
## 3. 使用规则

1. 先判断信息属于“项目事实、推断还是未解决问题”，不要用未经验证的推断回答外部开发者。
2. 外部问题尽量提供最小可复现材料、预期行为和验证证据，不粘贴完整内部上下文。
3. 内部模板只作为实现参考，不直接复制到公开仓库；公开内容应重新表述为组织无关的方法论。
4. 对外发布前必须完成脱敏检查和相应审批。没有审批记录时，默认不发布。
5. 文档和脚本 PR 只解决通用问题；不要借 PR 传递公司项目的隐藏约束、私有集成或敏感上下文。
6. 如果外部反馈会改变当前项目事实、工作约定或长期维护责任，再同步更新项目上下文或迭代日志；普通讨论不自动改变项目事实。

## 4. 推荐的交流顺序

外部交流按以下顺序组织：

1. **说明问题**：目标、背景、当前行为、预期行为和影响范围。
2. **限定边界**：明确哪些内容已经脱敏，哪些内部细节不在讨论范围内。
3. **提出方法**：使用通用术语描述方案，列出替代方案和兼容性影响。
4. **给出证据**：提供公开链接、最小复现、测试结果或可重复命令。
5. **确认交付**：说明是讨论、文档修订、脚本变更还是开源 PR，并记录后续责任人。

## 5. 版本和责任

本目录的资料面向外部沟通，不能替代：

- 当前项目事实：见 `agent/context/project-context.md`；
- 单轮实施证据：见 `agent/context/iteration-log.md`；
- 项目内 Agent 工作规则：见 `AGENTS.md` 和 `CLAUDE.md`；
- 当前业务能力和未来规划：见 `agent/product/business-overview.md` 与 `agent/product/business-planning.md`。

外部资料与项目源码发生冲突时，以当前源码和受影响路径的验证结果为准，并在需要时更新相应的项目上下文。
