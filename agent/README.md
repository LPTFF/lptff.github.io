# agent/：人的项目工作台

`agent/` 用来降低理解、判断和验证成本，不是 Agent 的控制面。执行原则以根目录 [AGENTS.md](../AGENTS.md) 为准；这里只提供项目事实和任务入口。

## 工作方式

- 从用户结果出发，直接读取受影响代码和一份最相关资料；不为“完整理解”遍历文档。
- 现有功能满足需要时以维护为主；概念分析、历史路线图和缺少使用记录不自动成为新需求。优先解决用户指出的真实问题，不为证明产品价值增加用户劳动。
- 优先复用有效能力，以最小、可撤销的改动解决问题；不因惯例或已有实现限制方案空间。
- 在授权范围内主动自动化搜索、比较、实现、排错和真实重测，直到结果收敛或出现明确阻塞。
- 真实环境结果优先于源码推断；无法观察的部分保持未知，不用整齐的报告掩盖证据不足。
- 私人数据、本机状态和外部副作用按最小权限处理；人负责价值取舍、高风险授权以及提交、推送前的最终审查。

## 模型工作与持续检验

用实际维护与业务任务持续检验模型，每次工作优先留下能减少下一次维护的产物；不为评测制造需求、另建管理平台或要求用户填写台账。

- **GPT6 等复杂任务模型**：承担诊断、设计和复杂修复，关注问题是否解决、是否引入回归、人的纠正与接管次数，以及总耗时和费用。模型名称不是能力证明，按具体任务结果判断。
- **Gemini 等日常自动化模型**：承担有明确输入、输出和失败边界的重复任务，关注误判、漏判、恢复能力和成本。请求成功、格式合法与分类质量分别判断。
- **普通程序**：承接已确定的计算、转换、去重、状态转换和权限检查，不为这些工作重复调用模型。
- **按变化回归**：修复真实失败时，若问题可能复发且检查成本低，留下最小可重跑案例；相关代码、提示、模型或配置变化时重跑受影响案例。模型调用复用已授权环境与预算，不因本约定自动外传数据或新增付费定时任务。
- **比较有依据**：案例保留最小输入、来自业务规则或已核验结果的预期、检查方式；评测逻辑与样本就近放在对应代码或 `project-support/`，不放在 `agent/`。比较模型时固定案例和条件，记录实际模型、代码或提示版本；波动结果按需复测，未知费用不估作事实。高级模型可分析失败，不能独自生成答案又作为唯一裁判。
- **复用运行证据**：正常运行沿用已有状态和摘要，关注有意义的退步、失败或需人决策的变化。持续调用不等于持续效果评测；离线样本不证明线上有效。具体证明范围遵循验收原则。

当前这是维护约定，不表示已经建成模型评测或监控系统。新增检查应能防止有价值的回归；检查本身的维护负担接近其收益时，应简化或退出。

## 仅保留的人工卡点

- 未明确授权时，不进入私人登录环境，不扩大观察字段，不执行交易、删除、外发或其他高风险动作。
- 每次提交和推送前，人必须审查确定的待提交版本、真实证据、未知、分支和远程；批准后内容变化则重新审查。
- 真实页面或截图仍需人查看时先完成证据交付，再关闭页面、服务或临时环境。

## 目录边界

- `src/` 与 `project-support/` 保存产品代码和交付链；`agent/` 保存仍有长期价值的事实、产品判断和参考资料。
- 不把可重新安装的依赖、凭据、登录态、真实私人数据、原始网络日志、临时测试产物或截图提交到仓库。
- 好的交接只说明目标、已证实结果、失败或未知、变更、证据和下一步；没有长期价值的过程材料应删除。
