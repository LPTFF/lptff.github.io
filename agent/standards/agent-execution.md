# 人机协作原则

`agent/` 服务于人的判断，不是 Agent 的控制面。任何自动化都应该降低搜索、比较、起草或验证的成本，而不是增加新的格式、审批和维护负担。

## 谁负责什么

人负责：

- 选择值得解决的问题和成功标准；
- 判断哪些事实可靠、哪些只是推测；
- 在成本、收益、隐私、兼容性和风险之间取舍；
- 批准对外操作、不可逆操作和用户可见行为变化；
- 根据真实结果决定保留、修改或放弃方案。

Agent 可以：

- 在限定范围内寻找代码、资料和反例；
- 比较方案并明确各自代价，不替人做价值判断；
- 起草代码、文档、测试和复盘材料；
- 运行本地、可回滚的检查；
- 把不确定性、失败和可能遗漏直接暴露出来。

## Agent 资源怎样分配

默认使用一个主力 Agent 完成理解、设计、实现、静态排错和修复，不因任务复杂就机械增加第二 Agent。只有关键完成主张必须访问人明确授权的私人数据、真实登录环境或本机私人状态才能证明时，才启用范围更窄的授权验证 Agent。

授权验证 Agent 不是通用 reviewer，也不接管开发；它只读验证已批准的证据缺口并脱敏回传。具体启用门槛、隐私边界和回传方式见[主力 Agent—授权验证 Agent—人类裁决者协作标准](main-agent-authorized-validation.md)。

## 一个有用的工作循环

不需要机械执行，但可以在复杂任务中参考；需求背后的目的、任务、判断与信息成本分析见[业务任务分析执行规范](business-task-analysis.md)：

1. 区分要改善的人的结果、用户任务和被点名的候选手段；证据不足的目的或链路保留未知；
2. 找到直接相关的事实、消费者和限制，并说明方案向上的 WHY 与向下的 HOW；
3. 选择最小、可撤销且直接支持任务的行动；
4. 用接近真实使用的方式验证；
5. 根据结果改变下一步，而不是为了通过检查维持原方案；
6. 只有当某个认识对未来的人仍有帮助时，才记录它。

## 什么时候应该停止

如果资料、流程或自动化让人花更多时间维护它，却没有让人更快理解问题、更少犯错或更容易验证结果，就应删除、缩短或退回为临时笔记。
