# 真实环境验收原则

本项目只以目标真实环境中的实际操作结果符合人的预期作为验收通过依据。验证方法必须匹配真实消费者、真实数据来源、真实浏览器或运行时、真实网络与存储状态以及实际部署环境；不能由 Agent 自行设计一套更容易通过的替代环境。

## 唯一完成标准

- 页面与交互：在实际部署页面和目标浏览器中操作，观察 DOM、路由、Network、Console、存储、刷新、失败与恢复路径。
- 浏览器扩展：使用用户实际加载的扩展目录、真实 Chrome profile、真实站点登录态和真实消息链路；隔离浏览器或仓库外旧副本不能替代。
- 外部接口与采集：执行目标服务的真实请求，检查实际参数、分页、响应结构、错误、重试、数据时间和消费者结果。
- 数据与存储：核对真实来源、真实写入、去重、覆盖范围、刷新后状态和最终页面消费，不用自造记录替代。
- 部署：在实际发布环境观察构建产物、路由、资源、网络请求和用户路径；本地构建成功不等于部署通过。

只有对应真实环境中的关键路径和预期结果都已实际观察，才能标记 `PASS` 或“已验收”。

页面和扩展验收应选择能直接观察目标环境的工具。需要登录态、已加载扩展或既有本地存储时，连接用户实际使用的浏览器；只验证公开页面或本地组件时，可以使用 in-app browser、Playwright 或其他隔离环境，但必须把结论限定在该环境。某个控制器不可用时，应切换到同等可信的执行路径或修复测试基础设施，不因工具名称不同直接停止。

### BOSS 直聘特例

BOSS 的反自动化和异常环境识别可能使 DevTools/CDP/自动化浏览器改变真实页面行为，因此 BOSS Extension 的最终验收禁止使用 Chrome DevTools MCP、CDP、Playwright、Puppeteer、Selenium、WebDriver 或 remote debugging 控制线上页面。只允许普通用户 Chrome、真实登录页面和 OS 级 screenshot/mouse/keyboard；不得研究或规避自动化指纹、站点检测或专用字体保护。完整步骤、基础设施修复顺序和结论状态见 [`../verification/boss-extension-real-validation.md`](../verification/boss-extension-real-validation.md)。

## 不能作为验收的材料

源码阅读、语法检查、类型检查和构建只用于让产物能够进入真实环境。项目不维护以 Mock、fixture、单元测试或自设 Oracle 代替真实操作的完成门禁。

页面生命周期、第三方站点兼容性、数据链路和外部副作用均在对应真实环境验证。报告只记录真实操作直接证明的范围以及仍未执行的场景。

## 结论状态

- `PASS`：目标真实环境已完成实际操作，结果符合明确预期。
- `FAIL`：目标真实环境已完成实际操作，结果不符合明确预期。
- `BLOCKED`：缺少授权、无法接管目标环境、来源条件不成立或外部状态阻止操作。
- `未验收`：实现或静态排错已完成，但尚未执行目标真实环境操作。
- `未知`：当前事实不足，不能判断结果。

不得把“未观察”“无法访问”“静态检查通过”或“模拟输入符合预期”改写为 `PASS`。

## 最小执行顺序

1. 明确人的预期、目标环境、实际消费者、允许操作和停止条件。
2. 先观察真实现状和失败证据，再决定修改位置；不得从自设样例反推项目事实。
3. 修改后可运行静态检查和构建排错，但不得据此结束验收。
4. 在同一目标真实环境重新执行关键用户路径，比较修改前后的实际结果。
5. 将实际结果与需求、原始失败、成功路径以及刷新、重载和恢复预期逐项比对；有差异就回到第 2 步继续定位和修改。
6. 重复“观察 → 修改 → 真实重测 → 分析比对”，直到全部约定预期通过，或出现无法在当前权限和环境内解除的明确阻塞。
7. 记录本次真实证据直接证明的范围、没有证明的范围以及剩余风险。

静态检查成功只能允许进入下一轮真实重测，不能成为停止条件。Agent 不应把“请用户自行验证”作为页面或扩展修改的默认交付方式；只要已经获得目标环境的操作授权且接管通道可用，就应自行完成上述循环。只有接管通道、目标 profile、实际加载目录、登录态或授权确实不可用时，才可以 `BLOCKED` 结束，并写清已经检查的事实和解除阻塞所需的单一条件。

核心判断是：**目标真实环境中的实际操作结果是否符合人的预期。**
