# 真实环境验收原则

验收只回答一个问题：**目标真实环境中的实际结果，是否符合人的预期？** 工具、测试数量和报告格式都不是目标。

## 四条规则

1. **环境匹配主张**：页面、数据源、浏览器、登录态、存储、网络和部署中，哪些属于本次主张，就在对应环境实际操作。不能用更容易控制的替代环境扩大结论。
2. **静态证据只用于排错**：源码、类型检查、构建、Mock、fixture、脱敏快照和测试可以发现实现问题，但不能单独证明功能完成。
3. **失败驱动下一步**：先复现，再修改，再在同一目标环境重测；比较页面、路由、Network、Console、存储、刷新以及失败恢复。结果不符就继续修复或明确阻塞，不修改成功含义。
4. **证据最小且可审查**：只输出支撑结论所需的脱敏状态、字段和聚合计数，并说明没有证明什么。人尚未看见所需页面或截图时，不先关闭现场；证据交付后再清理临时服务，截图和私人原始材料不进入仓库。

## 验收工具与审查现场硬约束

- 项目或专项手册指定 Chrome DevTools MCP 时，必须先搜索当前会话中可直接调用和延迟加载的 `chrome_devtools` 工具，再判断能力是否可用。Chrome 浏览器扩展不可用、普通浏览器连接失败或工具未直接显示，都不能据此声明 Chrome DevTools MCP 不可用。
- 指定 Chrome DevTools MCP 的验收不得用 Codex 内置浏览器、普通 Browser 插件、Playwright、接口请求、构建结果或其他自动化表面替代。替代工具可以排错，但不能产生 `LOCAL_BROWSER_PASS`、`REAL_SOURCE_PASS` 或 `PRODUCTION_PASS`。
- 只有在完成工具发现，并且实际调用 Chrome DevTools MCP 仍失败后，才能声明 `BLOCKED`；声明时必须给出真实失败点，不能把尚未搜索的能力写成阻塞。
- “完成自动验收”和“完成用户审查”是两个阶段。只要用户尚未明确表示审查结束，就保留供审查的 Chrome 页面、目标标签、本地服务和必要滚动位置；不得以已经取证、已有文字结论或节省资源为由自行关闭。只有用户明确要求关闭、审查完成，或继续保留会产生安全风险时，才清理现场，并说明原因。
- 交付结论前检查一次审查现场：目标页面仍可访问、应查看的条目仍可定位、本地服务仍在运行。若此前误清理，先恢复现场再交付，不把恢复工作交还给人。

## 结论必须带环境

- `LOCAL_BROWSER_PASS`：本地运行代码已在声明的浏览器和本地 origin 完成实际操作；不代表已部署或真实来源通过。
- `REAL_SOURCE_PASS`：用户授权的真实来源、登录态、数据链和实际消费者已完成相应只读操作；不代表生产版本已包含未部署代码。
- `PRODUCTION_PASS`：目标生产部署中的用户路径已实际完成。
- `FAIL`：已执行的真实结果与预期不符。
- `BLOCKED`：授权、接管通道、目标环境或外部状态使真实操作无法完成。
- `未验收 / 未知`：尚未实际观察，或事实不足。

禁止不带环境范围的笼统 `PASS`，也禁止把一个环境的结果扩写到另一个环境。

## 权限与隐私

- 进入私人登录环境前，明确目标页面、允许观察的数据、允许动作和停止条件；浏览器访问授权不自动包含交易、删除、外发或扩大字段范围。
- 默认只读；不得输出或保存凭据、Cookie、Token、账户、银行卡、原始 Network Log、原始账户数据、基金名称、金额、收益或可组合识别个人的信息。
- 若只有私人真实环境能补足证据，按[最小授权验证](main-agent-authorized-validation.md)执行；无法在边界内取得证据时返回 `BLOCKED/UNKNOWN`。

## 页面特例

- **Investment Review**：使用 Chrome DevTools MCP 接管用户实际 Chrome；验收真实页面、IndexedDB、来源附件、刷新与恢复。未部署代码只能取得 `LOCAL_BROWSER_PASS`，真实数据验证只回传脱敏结论。
- **BOSS 直聘扩展**：反自动化环境下禁止 DevTools/CDP/WebDriver，严格按[BOSS 专用手册](../verification/boss-extension-real-validation.md)使用普通 Chrome 和 OS 级操作。

除此之外，根据主张选择能直接观察目标环境的 DevTools、浏览器、桌面操作、接口或运行时；工具名称不是目的，证据等价性才是判断标准。
