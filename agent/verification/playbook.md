# Agent 可信验证 Playbook

本清单用于行为、数据流、采集、复杂 UI 和部署变更。它补充 `AGENTS.md` 的运行标准，不替代任务判断。

## 1. 建立基线

- [ ] 记录目标、受影响数据链、现有消费者、明确不做的范围和验收条件。
- [ ] 区分已确认事实、推断和未解决项；源码与上下文冲突时以受影响源码为准并同步上下文。
- [ ] 记录将使用的工具、运行环境、端口、代理、数据目录和启动条件。
- [ ] 一次性标明本轮持续授权与人工门禁：确认后自动推进范围内的本地可逆步骤；行为/架构变化、未授权外部操作、破坏性覆盖、凭据/付费资源或安全边界变化才重新确认。
- [ ] 将任务拆成可恢复阶段，明确每阶段输入、输出、验收门槛、失败策略和检查点；通过任务状态展示当前阶段、已完成项、阻断项与下一步。

## 2. 实施与局部契约

- [ ] 保持修改局部、可回滚；不以新增平行页面绕过现有消费者问题。
- [ ] 运行相关 fixture、单元测试、类型检查和编译。
- [ ] 对采集器验证 HTTPS/白名单、超时、响应大小、挑战页、Schema、最低条数、重复项和敏感字段。
- [ ] 模拟异常，证明失败不会覆盖最后有效数据或发布半成品。
- [ ] 同构目标按矩阵批量执行并统一汇总；独立操作并行、有依赖操作流水线化，结果映射回具体文件/来源/视口/用例，失败项支持定向重试。
- [ ] 不把破坏性操作混入批次，不通过无限并发触发外部限流，也不因批量处理丢失单项错误归因。

## 3. 真实执行和产物

- [ ] 真实运行项目记录的采集/生成命令，而不只调用 parser 或 mock。
- [ ] 对每个脚本记录 `success`、`preserved`、`skipped` 或 `failed`，并记录耗时、条数、是否变化及脱敏原因。
- [ ] 验证真实产物的 Schema、最低条数、URL、重复项、批次/manifest 一致性和敏感信息。
- [ ] 不把退出码 0、HTTP 200 或 JSON 可解析单独称为业务成功。

## 4. 现有消费者和业务结果

- [ ] 使用生产构建和 `vite preview`，确认未误命中开发代理或历史远程数据。
- [ ] 打开现有业务路由，确认真实产物被 Vue 页面消费；直接打开 JSON 或独立 HTML 不计入闭环。
- [ ] 检查桌面和相关移动视口、关键交互、网络请求、控制台、图片和链接。
- [ ] 将业务阻断问题与无关外部资源噪声分开记录。

## 5. 结论—证据映射

- [ ] 先保存机器证据，再写结论；不要从叙述反推采集参数、DOM 指标或网络状态。
- [ ] 每项关键结论明确写出“事实观察 → 推导结论 → 事实依据”，并说明证据不能证明什么。
- [ ] 事实观察引用具体字段，例如 `state`、`itemCount`、`newItemCount`、`timestampAdvanced`、响应 `content-type`、DOM 数量、破图/横溢和 console 计数。
- [ ] collector/接口结果、产物校验、浏览器指标/网络、截图各司其职；截图不替代接口参数和字段语义，JSON/HTTP 200 不替代现有消费者。
- [ ] 成功闭环至少链接“真实执行结果 + 产物校验 + 现有消费者指标”，涉及可视状态时再链接桌面和相关移动截图。
- [ ] 阻断/否定结论链接缺失字段、挑战/授权边界或 DOM 隔离证据；没有运行账号态请求时明确写“无该等级证据”，不制造截图。
- [ ] 在 `current/index.json` 的 `claims` 中登记当前关键结论；每项证据直接指向 `current/assets/` 文件，不只链接目录或写“见报告”。
- [ ] 运行 `npm run test:verification-reports`，确认缺少 inference、缺少证据、路径越界、未知类型或文件不存在都会失败。
- [ ] 运行 `npm run verification:refresh` 两次并比较输出，确认 `latest.md` 确定性生成且未解决项可跳到对应推导与证据。

## 6. 产品合同与外部阻断

- [ ] 区分产品目标、采集技术、数据合同和当前新鲜度；采集入口失败不自动意味着产品目标应删除。
- [ ] 用户未明确授权改变产品范围时，不通过删除 source、registry、JSON、菜单或消费者来关闭报告项，也不使用其他平台替换原采集目标。
- [ ] 历史快照按与新候选相同的 Schema、唯一性、安全约束判断；不合格时选择“保留但不消费”，合格但过期时在页面明确 `stale/preserved`。
- [ ] 缺凭据、挑战页、TLS/HTTPS、显式字段或授权时，记录合法尝试、未使用的绕过方式、所需外部输入和责任人，状态保持 `preserved`、`skipped` 或 `blocked`。
- [ ] 用户纠正过的产品合同增加回归测试或只读检查，避免后续 Agent 再次通过物理删除制造“完成”。

## 7. 报告与收尾

- [ ] 在被 Git 忽略的 `agent/verification/reports/` 保存报告与必要截图/机器摘要；`latest.md` 只通过生成命令更新。
- [ ] 报告包含：基线、工具与启动条件、脱敏命令、产物校验、页面/网络/控制台、失败与跳过、复现步骤、剩余风险和责任。
- [ ] 明确每项证据证明什么、不能证明什么；事实链缺环时标为部分完成。
- [ ] 判断本轮失败经验是否需要进入规则、测试、checklist、playbook 或只读检查。
- [ ] 恢复不应进入 Review 的动态数据、生成声明、截图、报告和临时目录。
- [ ] 运行 `git diff --check`、`npm run iteration:report` 和 `npm run context:check`。
- [ ] 未经明确授权不提交或推送；只说“推送远程”但未指定分支时先确认目标分支。
