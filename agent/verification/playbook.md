# 真实验收任务手册

结论状态、隐私和证据要求统一以[真实环境验收原则](../standards/trusted-verification.md)为准。本页只帮助快速选择执行路径。

## 选择路径

| 变更 | 真实消费者与重点 |
| --- | --- |
| 普通页面、路由、组件 | 与主张匹配的浏览器和 origin；操作关键路径，观察路由、Console、Network、刷新和失败恢复 |
| 本地数据或 IndexedDB | 实际页面写入、去重、版本、刷新后状态和最终消费者；不以自造记录代替真实来源结论 |
| 外部接口或采集 | 目标服务的真实请求、分页、错误、重试、Coverage、数据时间和页面消费 |
| 部署 | 实际生产 URL、资源、路由、网络和用户路径；本地构建不代表部署完成 |
| Investment Review | 用户实际 Chrome + Chrome DevTools MCP；只输出脱敏状态和聚合计数，未部署代码仅可声明 `LOCAL_BROWSER_PASS` |
| BOSS 扩展 | 改用[BOSS 专用手册](boss-extension-real-validation.md)，禁止 DevTools/CDP/WebDriver 控制线上页面 |

## 一次闭环

1. 明确人的预期、环境、消费者、允许动作和停止条件。
2. 在目标环境复现现状，记录直接失败证据。
3. 修改后回到同一环境重新操作；静态检查只帮助排错。
4. 核对成功路径、刷新、重复操作、失败和恢复中与改动相关的部分。
5. 给出带环境的结论、直接证据、未证明范围和剩余风险。
6. 人仍需查看页面或截图时保留现场；交付完成后再清理，私人材料和截图不进入仓库。

工具不可用时先修复执行层或寻找证据等价的路径。只有授权、接管、目标 profile 或外部条件确实无法满足时，才返回 `BLOCKED`，不得用隔离环境、旧 JSON、测试或源码推断冒充完成。
