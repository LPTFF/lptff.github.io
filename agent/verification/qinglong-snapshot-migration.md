适用：公开采集迁移、页面没有新数据、复核其他 Agent 宣称“已完成”。这是 2026-09-19 成功实践提炼；不能当作未来提交、部署或历史改写授权。

## 当前责任边界

- 2026-09-20 维护者明确：服务器采集只使用 HTTPS 接口请求，接口做不到就暂时搁置；不安装或启用服务器 Chromium / Playwright 采集。用户本机扩展授权采集及内网 HTTPS 同步是独立辅助路径，不算服务器独立自动采集。
- 私有 `qinglongBackup/src/site_crawlers/manifest.json` 管理服务器采集，青龙产生数据后推送本仓库 `python-crawl` 分支。
- 本仓库 `master` 只负责页面与构建；`.github/workflows/code-deployment.yml` 恢复公开快照并发布 Pages，不重新采集来源。
- 旧 Python/RSS 实现归档私有仓库 `research/legacy-site-collectors/`；不要恢复 `project-support/crawl/`、`project-support/scripts/collectors/` 或 `data-crawl.yml`。
- 页面关键词配置在 `src/config/welfare-keywords.json`。浏览器授权扩展、站主 Issue 研究书签同步有独立用途，不随服务器采集一起删除。
- 后端操作的唯一详细指南是私有仓库 `agent/docs/site-crawler-migration-review.md`，从其 `agent/README.md` 可进入。公共文档不复制服务器凭据、环境配置或完整会话日志。

## 执行顺序

1. 读取根 `AGENTS.md`，检查分支、HEAD、暂存区和已有修改。只改用户授权的范围，其他工作保留原样。
2. 从页面 import 倒查发布 JSON，再对照后端 manifest 的本地与远程路径。不能根据文件名猜目录；Hamibot 的本地路径和网页消费路径不同。
3. 修采集问题去私有仓库，修显示问题才改前端。不新增第二套公开采集，不把浏览器旧缓存拼入已迁移来源来掩盖缺数据。
4. 删除采集支持目录前，先迁出页面仍需要的纯显示配置，再搜索 `src/`、工作流、npm 配置及构建配置中的旧引用。历史资料可注明旧路径，活动依赖不能继续引用它。
5. 执行类型检查、生产构建、`verify-public-whitelist.cjs dist`，并在真实 Chrome 验证来源筛选。生成的时间戳文件若只是本次构建副产物，不夹带提交；不能覆盖原有用户修改。
6. 审核准确差异并取得提交/推送授权，只暂存指定文件。推送后按准确 SHA 找 Pages 运行；之前成功的运行不算本次证据。
7. 从 GitHub 默认分支树确认旧代码和旧定时工作流已消失，再核对活动工作流与仍在执行的旧任务。仅本地注释 cron 不算关闭线上旧写入者。
8. 等本次 Pages 发布成功，刷新线上页面，检查实际加载资源、来源筛选和日期语义。留下运行链接和聚合结果供用户审查；未验证的范围直接说明。

## 易错点与停止条件

| 检查项 | 正确判定 |
| --- | --- |
| 数据更新但网站未更新 | 数据分支和 Pages 是两阶段；先看本次部署读取了哪个快照，再看页面资源，不能只反复运行采集 |
| 快照获取失败 | 必须停止构建；禁止加 `|| true` 让旧数据伪装成新发布 |
| 自定义数据引用 | 只允许 `python-crawl` 或完整 SHA；经环境变量传入，不能直接拼接用户输入到 shell |
| 退出码 0／保留旧数据 | 不等于新采集成功；检查结构化状态和真实产物，不要求失败来源必须清空数据 |
| 本地和线上条数不同 | 核对快照时间、来源与筛选口径；旧存量计数不是永恒断言 |
| 推送被拒绝或远程已变化 | 重新检查分支和他人提交，不强推；有冲突或范围变化先向用户说明 |
| 密钥、Cookie、完整请求日志 | 不输出、不写公共仓库、不打包；校验仅输出必要元信息 |
| 想让所有任务变绿 | 不擅自启用后端原本禁用的采集器，不删除失败状态来伪造成功 |
| 要从历史中抹掉源码 | 普通删除提交做不到；单独提出历史改写风险并取得授权 |

旧接入手册中“在 GitHub 配采集定时任务”的流程仅作为迁移前资料，不用于恢复公开采集。页面和扩展的独立功能仍按对应手册验收。
