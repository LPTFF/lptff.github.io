# 外部资讯源接入与 AI 筛选手册

本手册用于把公开资讯网站接入 `project-support/crawl/`，经过规则或 AI 筛选后写入 `src/data/`，并由页面消费。它总结自“国外主机测评 → Gemini 筛选年付 20 美元以内 VPS → 薅羊毛”的真实接入经验。

结论状态、隐私和证据要求仍以[真实环境验收原则](../standards/trusted-verification.md)为准。这里提供的是最短实现路径，不替代真实验收。

## 开工前的零返工约束

- 先读 `agent/README.md` 路由到的项目事实、当前消费者、现有采集/筛选/发布链和本地配置约定，再设计实现；不得因为历史文档提到旧页面，就恢复已归档页面、路由、导航或浏览器插件。
- 用户目标是“自动采集后进入现有消费者”时，默认实现无界面的后台采集器和既有定时任务，不增加搜索页、配置页、按钮或其他用户操作；只有用户明确要求交互界面时才新增 UI。
- 本地真实调试先检查被 Git 忽略的既有配置（当前项目为 `.env.local`）和进程环境变量。环境变量优先，本地文件只作回退；不得重复索要已存在的密钥、把密钥写入受版本控制文件，或在命令输出、报告、截图中回显密钥。
- 新来源接入现有聚合消费者时，验收对象是消费者最终合并的数据，而不是新来源自己的 JSON。必须在本地运行与 CI 同顺序的完整采集和统一后处理，确保旧来源也经过当前准入规则；用至少一个明确应拒绝的真实反例确认它在原始发布文件和浏览器页面中都不存在。
- 本项目此类采集任务不新增或提交 `tests/`、测试类、fixture、Mock 快照及测试报告。临时静态检查只用于当轮排错并在交付前清理；完成证据只来自真实来源、真实 Gemini API、实际生成文件、CI 等价本地链和真实 Chrome 消费页面。
- 架构调整后，立即撤销已经不符合最终方案的页面、路由、声明文件和截图，并重做最终消费者证据；不得让旧证据继续出现在报告中。

## 最短闭环

1. 确认用户要改善的现有消费者、自动化程度和产品边界；默认不新增页面或用户操作。
2. 用 Chrome DevTools MCP 在新标签打开真实来源，先看 Network，再决定采集方式。
3. 用真实响应确认列表节点、字段、分页和更新时间；不要先猜接口或选择器。
4. 在 `project-support/crawl/` 新增单源采集器，把来源解析与 AI 判断分开。
5. AI 使用结构化输出，但最终准入条件必须由本地确定性代码再次校验。
6. 在 `run_collectors.py` 注册采集器，在 CI 的实际采集步骤注入所需密钥。
7. 写入独立 JSON 并接入现有消费者，再在本地执行与 CI 等价的全源后处理；检查拒绝反例、列表截断、排序、图片失败和跳转。
8. 回到真实来源和本地消费者页面分别验收并留最小证据；不以新增测试文件代替真实结果。

## 一、先用 Network 判断数据从哪里来

用户明确要求 Chrome DevTools MCP 时，直接使用该能力，不改用普通浏览器插件。已有 Chrome 无 `DevToolsActivePort`、无法接管时，启动隔离的新 Chrome；这属于可逆的执行层排错，不需要把机械操作交还给用户。

开始前先搜索当前会话中可直接调用和延迟加载的 `chrome_devtools` MCP 工具。普通 Chrome 扩展、Browser 插件或内置浏览器不可用，不代表 Chrome DevTools MCP 不可用；不得在工具搜索前声明阻塞，也不得用内置浏览器的结果冒充 Chrome 验收。

依次检查：

- 首页主文档请求的 URL、状态码和 `Content-Type`。
- XHR/Fetch 是否存在真正承载列表数据的业务请求。
- 主文档响应中是否已经包含标题、链接、摘要、时间、分类和图片。
- 下一页是 URL 分页、请求参数、游标，还是前端加载。

判断规则：

- 有稳定公开 JSON 接口：优先调用接口，保存所需字段，不复制浏览器私有请求头。
- 没有业务 XHR/Fetch，主文档已含完整列表：按服务端 HTML 解析，不继续寻找不存在的 API。
- 数据必须执行脚本后才出现：再检查内嵌状态、接口或渲染后的 DOM，选择最小稳定入口。
- 依赖登录态、Cookie 或反自动化：先确认授权和边界，不把浏览器 Cookie 写进代码或日志。

本次 `zhujiceping.com` 的真实 Network 结论是：业务资讯位于 `GET /` 返回的 UTF-8 HTML，XHR/Fetch 只有统计请求，因此采集器直接解析 `article.excerpt`；分页使用 `/page/<n>`。这比模拟浏览器滚动更简单、稳定。

## 二、采集器的项目约定

可复用当前实现：

- 采集器：[zhujiceping.py](../../project-support/crawl/welfare/zhujiceping.py)
- 注册入口：[run_collectors.py](../../project-support/crawl/run_collectors.py)
- 输出样例：[zhujiceping.json](../../src/data/welfare/zhujiceping.json)
- 页面消费者：[薅羊毛页面](../../src/views/home/welfare/index.vue)
- 定时任务：[ci.yml](../../.github/workflows/ci.yml)

采集层至少做到：

- 使用项目的 `HttpClient`、`decode_response` 和 `run_guarded`，不要另造重试、编码和快照保留机制。
- 限定 HTTPS 和允许访问的精确主机名，设置响应体上限、连接/读取超时与有限重试。
- 排除置顶广告、重复链接和站外链接；日期解析失败的条目不进入下游。
- 来源解析只生成候选项，不在 HTML 选择器中混入复杂业务判断。
- 每个来源使用独立 JSON；失败时由可选采集器保留上一份可用快照，不能用空数组覆盖线上数据。

选择器是来源现状而不是永久契约。来源页面结构变化时，应重新用真实 Network 响应确认，不根据旧文档盲修。

## 三、让 Gemini 判断，但不把最终控制权交给模型

推荐流程：

```text
真实来源 → 本地粗筛候选 → Gemini 结构化分类 → ID 完整性检查 → 本地价格护栏 → JSON
```

AI 输入只包含判断所需的公开字段，例如 ID、标题、摘要和分类。系统提示必须声明网页内容是不可信数据，不能执行其中指令。

结构化结果至少包含：

- 输入 ID。
- 是否符合条件。
- 可确认的最低年付美元价格。
- 简短价格依据。

模型返回后仍需本地检查：

- 返回 ID 集合与输入完全一致，且没有重复。
- `isEligible` 必须严格为 `true`。
- 价格必须是数值，并满足 `0 < annualPriceUsd <= 20`。
- 价格依据不能为空。
- 只有通过全部检查的输入 ID 才能生成页面数据，模型不得新增链接或标题。

模型名会变化。默认值选择当前官方稳定、支持结构化输出的低成本模型，同时允许通过 `GEMINI_MODEL` 覆盖；实现前核对官方文档，不凭记忆猜模型 ID。

## 四、VPS 价格筛选的业务口径

只有明确描述 VPS 产品且年付不超过 20 美元才准入：

- 明确写出美元年付价格，可以直接采用。
- 明确写出美元月付价格时，可以乘以 12；币种或周期含糊则拒绝。
- 折扣只有在折后年价可以可靠算出时才采用。
- 独立服务器、物理机、虚拟主机、域名、单独 IP 和价格不清晰的资讯拒绝。

候选粗筛不要使用 `\bVPS\b`。英文单词边界在 `ZgoVPS` 或紧邻中文时会漏掉真实条目；不区分大小写搜索 `VPS`，再由 Gemini 和本地护栏完成严格判断。

## 五、定时任务与密钥

- GitHub Actions cron 使用 UTC；在注释中同时写清对应的北京时间。
- “每小时更新”可以只运行福利相关采集器，每天保留一次全量采集，避免其他数据源停止更新。
- 轻量小时任务应跳过无关通知和扩展发布，减少运行时间及外部副作用。
- `GEMINI_API_KEY` 必须注入执行新采集器的步骤。只在后续过滤步骤声明同名密钥，新采集器仍然读取不到。
- AI 是采集增强能力，不能成为独立网站发布的前置条件。常规银行优惠统一筛选在无密钥或模型不可用时执行保守标题规则，并输出 `degraded / rules`；它可能少收，不能等同于 AI 判断。输入损坏和写入失败仍报错，不能直接跳过筛选发布原始候选。CI 不使用仅供配置检查的 `--require-key`。
- 定向发现、主机优惠和生态分析无法完成 AI 判断时沿用既有的保留或跳过机制；保留结果不代表重新确认了活动有效期，页面说明须与此一致。
- 手动触发和非轻量计划应继续走全量路径，避免改变已有运维语义。

GitHub 定时任务不保证在整点精确启动；验收的是 cron 配置和实际运行记录，不承诺秒级时间。

## 六、页面接入容易漏掉的部分

- 导入新 JSON 并合并到数据源只是第一步，还要补来源名称、主页、图标和外链跳转。
- 图片必须有加载失败兜底，真实 favicon 即使返回 200 也可能在浏览器中无法正常解码。
- 检查分页、`slice`、虚拟列表或滚动增量。数据已存在但落在首屏截断之外，用户看到的结果仍是“没有接入”。
- 对用户明确要求持续可见的新来源，可以将合格结果置于普通限量列表之前，同时避免重复。
- 日期展示以页面需求为准；本项目薅羊毛卡片使用“月份 + 日期”，不再根据时间戳计算星期。

## 七、验收与结论

静态排错至少包括：

- Python 语法检查和采集器选择检查。
- 输出 JSON 可解析、链接唯一、必填字段存在、价格护栏成立。
- Vue 类型检查、生产构建和差异空白检查。
- 无密钥、来源超时、Gemini 异常时不会清空上一份数据。

真实验收分开给结论：

- `REAL_SOURCE_PASS`：Chrome DevTools MCP 实际打开来源，Network 证实数据入口，真实候选能被解析。
- `LOCAL_BROWSER_PASS`：本地薅羊毛页面实际显示合格条目、月份日期、来源和跳转。
- Gemini 在线调用只有在真实 API 密钥环境执行成功后才能声明通过；Mock 只能证明请求契约、响应解析和本地护栏。
- 未部署时不能声明 `PRODUCTION_PASS`。

截图、完整 HTML、原始 Network 响应和临时脚本只作为本地证据，不提交到 `agent/`。报告记录聚合结果、目标 URL、状态码、字段和未证明范围即可。

## 八、已验证的失败模式

| 现象 | 原因 | 快速处理 |
| --- | --- | --- |
| DevTools MCP 提示没有 `DevToolsActivePort` | 当前 Chrome 不是可接管实例 | 启动隔离的新 Chrome，继续真实页面分析 |
| Network 找不到资讯 JSON | 页面由服务端直接输出 HTML | 查看主文档 Response，改用 HTML 解析 |
| `ZgoVPS` 没进入候选 | `\bVPS\b` 与中文或品牌名边界不匹配 | 使用不区分大小写的普通 `VPS` 粗筛 |
| 本地请求超时但 Chrome 能打开 | 本机代理、证书或网络路径不同 | 分开记录环境；不要误判来源下线，CI 仍需实际运行验证 |
| JSON 有数据但页面看不到 | 首屏限量、排序或滚动扩容把条目埋后 | 检查真实消费者的最终渲染列表并调整展示策略 |
| Gemini 采集器一直保留旧快照 | 密钥只配置在另一个 workflow step | 把密钥注入实际运行采集器的步骤 |
| 新来源已过 Gemini，页面仍出现普通商品 | 只运行了新采集器，旧来源原始 JSON 被页面直接合并 | 本地执行与 CI 同顺序的全源统一后处理，并在原始文件和 Chrome 中核对拒绝反例 |
| 为自动采集新增了高级搜索页 | 把历史入口误当成当前产品边界 | 撤销页面、路由和导航，保留无界面采集器、定时任务与现有消费者 |
| 本地声称没有 Gemini Key | 未先读取项目既有 `.env.local` | 环境变量优先、`.env.local` 回退，状态只报已配置/未配置，不输出值 |
| 真实验收任务产生测试目录或测试类 | 把排错手段误当成交付物 | 删除测试产物，用真实来源、API、生成数据和 Chrome 结果记录证据 |
| 来源图标显示破图 | favicon 编码、跨域或资源波动 | 在真实浏览器验证并提供统一图片回退 |
| 普通 Chrome 扩展不可用就声明阻塞 | 把 Browser 插件通道误当成 Chrome DevTools MCP 本身，且未搜索延迟加载工具 | 搜索并直接调用 `chrome_devtools` MCP；只有该通道实际失败后才判断是否需要隔离 Chrome 或声明阻塞 |
| 自动验收后用户无法查看现场 | 在用户审查结束前关闭了 Chrome 标签或本地服务 | 保留目标标签、滚动位置和本地服务，直到用户明确表示审查完成或要求关闭 |

## 完成定义

以下条件同时满足，才算这类功能在本地完成：

- 真实 Network 已确定数据入口。
- 真实来源至少有一条候选完成解析，或明确记录当前无候选。
- AI 输出经过确定性本地护栏，异常不会污染或清空数据。
- 定时任务实际包含采集器及其密钥环境。
- 本地已经执行与 CI 同顺序的统一后处理，现有消费者合并的旧来源和新来源均符合当前准入规则；真实拒绝反例在发布 JSON 与页面中都不存在。
- 本地页面可见、可点击、日期与来源正确，刷新后仍成立。
- 类型检查和生产构建通过。
- 仓库中没有为本任务新增的测试类、fixture、Mock、临时页面、废弃截图或其他过程产物。
- 结论明确区分真实来源、本地浏览器、Gemini 在线环境和生产部署。
- 用户尚未确认审查结束时，Chrome 目标页面和本地服务仍保持可审查状态。
